# 행동 모델이 보는 것은 궤적이 아니라 상호작용 규모

조성원 · 2026-07-31 · 공동 측정: 김민서

---

## 결론

**직선으로 자로 그은 궤적이라도 객체를 여러 번 끌면 사람으로 판정된다.**

```
같은 궤적(linear) · 같은 타이밍(real) · 같은 도구

  드래그 5회   human_probability  1.0000  (n=5)
  드래그 1회   human_probability  0.0000  (n=5)
```

궤적의 사실성이 아니라 **상호작용의 규모**가 판정을 가른다. 봇에게 "여러 번 끌기"는
반복문 한 줄이고, 궤적을 사람처럼 만드는 것보다 압도적으로 싸다. **공격자는 쉬운
쪽으로 온다.**

---

## 어떻게 여기까지 왔나 (틀린 가설 두 개 포함)

이 결론에 이르기까지 가설을 두 번 틀렸다. 기록해 둔다 — 같은 함정을 다시 밟지
않기 위해서다.

### 가설 1 — "간격 지터가 축이다" ❌

처음 관측: 민서님 생성기(산술 타임스탬프)는 0.000000, 내 것(실제 sleep)은 0.9999.
→ "모델이 규칙적 간격 = 봇을 배웠다" 고 결론.

**틀렸다.** 네 조합을 다 계산하니 민서님 synthetic 의 간격 CV 가 0.471 로 내
것(0.239)보다 **오히려 불규칙**한데도 봇으로 잡혔다. 지터는 축이 아니었다.

> 교훈: 두 조합만 보고 축을 지목했다. 2×2 를 채웠어야 했다.

### 가설 2 — "속도·총시간이 축이다" ❌

수정된 가설: ms synthetic 780ms·속도 1.19 → 봇 / sw 1127ms·속도 0.69 → 사람.
→ "너무 빠르면 봇" 이라고 결론하고, **반대 방향의 예측**을 냈다.
"ms straight/real 은 2513ms·속도 0.394 로 더 느리니 사람으로 나와야 한다."

민서님이 그 빠진 셀을 실제로 돌렸다. **≈0 (봇). 예측이 정반대로 틀렸다.**

> 교훈: 반증 가능한 예측을 낸 것은 옳았다. 그 덕에 하루 만에 죽었다.

### 그리고 도구 교란

민서님 지적: "네 점수는 네 도구, 내 점수는 내 도구라 궤적 말고 payload 구성도
다르다." 맞았다. 확인해보니 구조적 차이가 있었다.

```
ms   oid = tg[0]          → 객체 1개만 드래그, 이벤트 ~14
sw   for obj in objects   → 전 객체 드래그, 이벤트 ~50 (5객체 기준)
```

궤적이 아니라 **상호작용 규모**가 달랐다.

## 통제 실험

### 1차 — 규모 축만 분리

도구·궤적·타이밍을 전부 고정하고 드래그 개수만 바꿨다.

| | n | 평균 human | allow |
|---|---:|---:|---:|
| `drag=all` | 4 | 0.999670 | 1 |
| `drag=one` | 5 | 0.000000 | 0 |

### 2차 — 다른 도구로 독립 재현 (김민서)

민서님이 자기 도구에 `--drag one|all` 을 넣어 같은 실험을 했다.

| | n | 평균 human | 사람 판정 |
|---|---:|---:|---|
| `drag=all` | 5 | 0.9987 | 5/5 |
| `drag=one` | 10 | 0.100 | 1/10 |

**서로 다른 구현이 같은 방향을 냈다.** 이 시점에서 도구 교란은 제거됐다.

### 3차 — 규모를 셋으로 쪼갠 sweep

`drag` 를 바꾸면 이벤트 수·총시간·드래그 횟수가 함께 움직인다. 셋을 분리했다.
각 조건에서 나머지 둘을 고정한다.

| 축 | 조건 | 평균 human | 판정 |
|---|---|---:|---|
| **A. 이벤트 수** | 이동 6 / 15 / 30 (드래그1·3초 고정) | 0.083 → 0.061 → 0.008 | ❌ 오히려 **감소** |
| **B. 총시간** | 0.9 / 3 / 6초 (드래그1·이벤트12 고정) | 0.000 → 0.089 → 0.158 | 약한 2차 효과 |
| **C. 드래그 횟수** | 1 / 3 / 5회 (이동 총 30·3초 고정) | 0.422 → 0.508 → **0.952** | ✅ **이것이 축** |

개별 값까지 보면 C 가 확실하다.

```
drag=1   0.000 0.000 0.001 0.566 0.968 0.994
drag=3   0.035 0.378 0.416 0.492 0.805 0.923
drag=5   0.773 0.938 0.968 0.989 0.998 1.000 1.000   ← 7/7 이 0.77 이상
```

`drag=5` 는 **최솟값이 0.773** 으로, `drag=1` 의 대부분보다 높다. 아래 서술할
노이즈를 뚫고 나온다.

### B 에서 건진 것 하나

`0.9초` 조건은 **7/7 전부 0.000** 이었다. 예외가 없다.

**1초 미만 완주는 확정 봇이다.** 다만 6초로 늘려도 0.158 까지밖에 안 오르므로,
시간만으로는 사람 쪽으로 못 넘어간다. 하한선으로만 쓸 수 있는 신호다.

## ⚠️ 이 sweep 의 결함

숨기지 않고 적는다. **A 와 B 의 미세한 차이는 믿을 수 없다.**

`swA-mv30` 과 `swC-d1` 은 파라미터가 완전히 같은 조건(드래그1·이동30·3초)인데
결과가 이랬다.

```
swA-mv30   0.000 0.000 0.000 0.001 0.001 0.001 0.051   평균 0.008
swC-d1     0.000 0.000 0.001 0.566 0.968 0.994         평균 0.422
```

**같은 조건인데 평균이 50배 다르다.** 챌린지마다 객체 위치와 드래그 거리가 달라서
생긴 변동이고, 내가 통제하지 못한 부분이다. `drag=1` 이 0.000~0.994 로 이봉분포인
것도 같은 원인으로 보인다.

- **A·B 는 결론으로 쓰지 않는다.** 방향만 참고한다
- **C 는 유효하다.** `d5` 의 최솟값이 `d1` 의 중앙값보다 높고, 민서님 도구가
  독립적으로 같은 방향을 냈다

제대로 재려면 챌린지 기하를 고정하거나 조건당 25~30건으로 늘려 평균으로 씻어내야
한다.

## 보안상 의미

### 공격 비용이 비대칭이다

```
궤적을 사람처럼 만들기     어렵다 (곡률·가속·지터 모델링)
객체를 여러 번 끌기        반복문 한 줄
```

그리고 **어려운 쪽을 안 해도 된다.** 자로 그은 직선을 5번 끌면 1.0000 이다.

### 정상 사용자에게도 문제다

정답이 1개인 문항을 푸는 사람은 드래그를 **1회만** 한다. 그 사람은 `drag=1`
분포(0.000~0.99)에 들어간다. 즉 **문항 유형이 사람의 점수를 좌우한다.**

이건 오탐 쪽 위험이고, 참여자별 FRR 을 잴 때 문항 구성이 교란으로 들어온다는
뜻이기도 하다. 사람 수집 때 정답 개수 분포를 기록해 둬야 한다.

### 지금 봇을 막고 있는 것은 이 모델이 아니다

허니팟(궤적과 무관), PoW(비용), 문제를 실제로 푸는 능력이 막고 있다.
행동 모델은 `shadow` 이고, `active` 로 올리기에는 이 축이 너무 쉽게 뚫린다.
