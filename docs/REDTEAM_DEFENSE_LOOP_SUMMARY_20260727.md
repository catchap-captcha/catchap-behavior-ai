## 4. 근본 한계 (기록만, 수정하지 않음)

사용자 지시에 따라 다음은 억지로 막지 않고 문서화한다. 클라이언트 제출형
프로토콜의 본질적 한계이며, 반응적 규칙으로 막으면 FRR만 악화된다(J-6에서
min-gap 규칙이 FRR 35% 유발 후 제거).

1. **짧은 녹화 재생**: `800ms` 미만 드래그(사람의 14.2%)는 스트리밍할 것이
   없어 전송 검사가 면제되고, 그 짧은 사람 녹화본을 버스트로 재생하면 통과.
2. **페이싱 실시간 재생**: 유효한 체인으로 원본 속도대로 실시간 전송하면
   서버 관점에서 진짜 사람과 구분 불가.
3. **모델 특징 계층**: FRR<3%에서 evader를 분리하는 안전한 단일 특징이 없음
   (최선 vel_cv 63.9%도 생성기 특성이라 사람 재생은 통과, weakset 과적합).

완전 차단은 클라이언트가 오프라인 재현할 수 없는 신호(수집 중 서버가 주입하는
실시간 challenge, 클라이언트 attestation)를 요구하며, 계약서 §8도 완전 증명은
클라이언트 측만으로 불가능하다고 명시. 운영 대응: 세션 위험 누적, 시도 제한,
요청 빈도 제한으로 반복 악용 비용을 높인다.

  연동으로 확보)가 모든 정책 승격의 선행 조건.
