## ① 기존 레드팀이 약했다

`redteam_weakness_search.py` 는 모션 정책을 **무작위로 뽑아** 회피한 것을 줍는다.
싸지만 시드에 크게 흔들린다. 같은 모델·같은 예산으로 시드만 바꿨다.

```
시드 20260804  회피 28    시드 20261804  회피  0
시드 20262804  회피 21    시드      777  회피  1
시드 20263804  회피 18    시드    12345  회피 17
```

**0건과 28건 사이를 오간다.** 한 시드로 "0건" 을 보고 방어가 됐다고 판단하면 안 된다.
실제로 오늘 오전에 내가 그렇게 판단했다가 뒤집었다.

### 진화 탐색

실제 공격자는 처음부터 다시 뽑지 않는다. **먹힌 것을 남기고 그 주변을 판다.**

```
정책 표본 → 채점 → 상위 개체 유지 → 그 주변으로 변이 → 반복
```

30세대를 돌리면 수렴한다.

```
현재 후보     1세대 1.9%  →  10세대 39%  →  30세대 47%   (후반 평균 47.4%)
```

**12세대쯤부터 44~52% 에서 평평해진다.** 무작위 스윕이 0.7% 로 보던 자리다.

## ② 약점셋을 학습에 넣으면 47% → 6%

`redteam_weakset_iter1` 2,554건은 7/22 탐색이 만들어 놓고 **학습에 넣지 않은 채
방치**돼 있었다. 넣고 다시 학습했다.

같은 사람 오탐률(개발 1.79%)로 맞춘 뒤 비교했다.

| | 현재 후보 | 패치 후 |
|---|---:|---:|
| 진화 탐색 회피율 (30세대) | 47.1% | **5.8%** |
| 다른 탐색이 만든 약점셋 | 70.0% | **0.0%** |
| 외부 holdout | 13.0% | **0.0%** |
| 미공개 절반 (학습에 안 넣은 쪽) | 44.0% | **0.3%** |
| 처음 보는 사람 오탐 | 1.62% | **1.17%** |

**사람을 더 막지 않으면서 전부 내려갔다.**

### 7/22 하드 네거티브 실패와 무엇이 달랐나

그때는 오탐이 2.39% → 9.06% 로 튀어 탈락했다. 넣은 데이터가 다르다.

```
7/22   inner-OOF 에서 임계값을 통과한 봇 782건 · 가중 3배
지금   약점 탐색이 찾아낸 궤적 2,554건 · 가중 1
```

7/22 은 **경계에 걸친 애매한 봇**을 강하게 눌렀고, 그러면 경계가 사람 쪽으로 밀린다.
지금은 **명백히 봇인데 통과하던 궤적**이라 사람 영역과 겹치지 않는다. 가중치도 3보다
1이 낫다(홀드아웃 1.40% vs 1.17%).

**"약점 학습은 안 된다" 는 결론을 나는 재검증 없이 받아 적었다.** 그게 오늘까지
이 항목을 막고 있었다.

## ③ 특징을 크기 정규화하면 3.3%

모델 특징 17개가 픽셀 단위다(`avg_speed`·`max_speed`·`displacement`·`jerk_mean` …).
픽셀은 `x_normalized × 스테이지 폭` 이라 **폭이 바뀌면 같은 손동작이 다른 숫자**가 된다.

지금 데이터에 이미 섞여 있다.

```
500px 422건 · 640px 43건 · 375px 34건 · 333px 28건 · 1024px 12건
```

캡차가 이미 보내주는 `x_normalized`(0~1)로 특징을 계산하면 폭 의존이 사라진다.
같은 사람 오탐률(1.98%)에서 비교했다.

| | 진화 탐색 회피율 (15~20세대) |
|---|---:|
| 픽셀 (현재) | 4.4 ~ 10.4% · 평균 **6.3%** |
| 정규화 | 2.7 ~ 5.0% · 평균 **3.3%** |

**떨어지기는커녕 절반이 됐다.** 절대 스케일이 판별에 기여하고 있던 게 아니라, 폭이
섞인 데이터가 잡음이었던 것으로 보인다.

### 연동에 대한 의미

**위젯 크기를 몇으로 하든 상관없다.** 반응형이어서 사용자마다 달라도 된다. 지금 모은
데이터와 나중 데이터를 섞어 쓸 수 있다. 크기 고정을 요청할 필요가 없다.

다만 **장치가 바뀌는 것은 별개다.** 폰 375px 은 "작은 500px" 이 아니라 손가락이
마우스와 다르게 움직인다. 터치는 여전히 따로 수집해야 한다.

## 오늘 네 번 뒤집었다

기록해 둔다. 전부 측정 도구가 부실해서 생긴 뒤집기다.

```
1차  "못 푼다. 기준을 나눠야 한다"            무작위 스윕만 보고
2차  "풀린다. 패치하면 0%"                   시드 하나에 속음
3차  "시드 분산이 커서 판정 불가"              시드 6개 재봄
4차  "47% → 6% → 3.3%"                     진화 탐색으로 상한을 재고
```

**측정 도구가 방어보다 먼저다.** 도구가 약하면 방어가 강해 보인다.

## 남은 확인 세 가지

**① 정식 파이프라인 재현.** 위 모델들은 내가 임시로 학습한 것이다. `training/` 의
정식 절차로 다시 만들어 같은 숫자가 나오는지 봐야 한다.

**② 처음 보는 사람 오탐.** 개발 데이터 기준이고, 정식 판정에는 새 홀드아웃이 필요하다.
레거시 사람 데이터는 8/04 로 전부 소진됐다. **수집 후에만 가능하다.**

**③ 메인 캡차 표면.** 위 실험은 전부 레거시 데이터다. 메인 캡차 데이터에서도 정규화가
같은 효과인지 확인해야 한다.

**④ 더 강한 공격자.** 3.3% 는 이 진화 탐색 기준이다. 특징 공간에서 직접 최적화하는
공격자를 만들면 다시 올라갈 수 있다. 다만 지금 도구 중에서는 이게 가장 강한 상한이다.
