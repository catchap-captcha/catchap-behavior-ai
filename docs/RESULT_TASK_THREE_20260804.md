## 먼저 — 1차 결론에서 틀린 것 두 가지

### ① "현재 후보는 사람 밀봉 평가를 한 번도 못 받았다" — 틀렸다

7/31 감사(B-2)에 그렇게 적었고 어제도 반복했다. 확인해보니 아니다.

```
models/candidate/revalidation_two_view_baseline_20260722/two_view_fusion.joblib
models/candidate/revalidation_two_view_participant_safe_20260722/two_view_fusion.joblib

  파일 해시     서로 다름
  점수          200행 전부 차이 0.000e+00
  fit_scope     동일 ("all non-lockbox revalidation development rows")
  threshold     0.9999501  vs  0.9999989      ← 이것만 다르다
```

**두 후보는 같은 모델이고 임계값만 다르다.** 따라서 `baseline` 이 소진한 직전
락박스(사람 2,045행 · 10명)는 **사실상 현재 모델을 평가한 것**이다.

감사 B-2 의 "지금 후보는 밀봉 평가를 한 번도 안 받았다" 는 문장은 파일 이름만 보고
쓴 것이고, 모델 내용을 대조하지 않았다.

### ② "Production 기준 ≤1% 통과" — 취소한다

같은 모델·같은 임계값으로 두 홀드아웃을 재보니 다르다.

| 데이터 (둘 다 처음 보는 사람) | 참여자 | FRR @ 0.99995 |
|---|---:|---:|
| 새 홀드아웃 | 7명 | **0.68%** |
| 직전 락박스 | 10명 | **2.20%** |

**3배 차이다.** 1차 보고는 새 홀드아웃 하나만 보고 "Production 기준까지 통과" 라고
썼다. 다른 쪽은 미달이다.

그리고 이 차이 자체가 결과다. **참여자 집단이 바뀌면 FRR 이 크게 흔들린다.**
7명·10명으로도 이 정도면, 메인 캡차의 2명은 훨씬 불안정하다.

## ② FRR (처음 보는 사람) — 진단이 바뀌었다

같은 모델·같은 임계값인데 표면에 따라 갈린다.

```
레거시 표면 · 처음 보는 사람 17명 (7 + 10)   FRR 0.7 ~ 2.2%
메인 캡차   · 처음 보는 사람  1명            FRR 4.5%
```

**"사람마다 달라서 일반화가 안 된다" 가 아니다.** 처음 보는 사람 17명에서 최대
2.2% 면 사람 축으로는 대체로 일반화한다. 문제는 **표면**이다.

어제까지 "사람이 부족하다" 고 했는데 정확히는 **"메인 캡차 표면의 사람 데이터가
부족하다"** 이다. 레거시 사람을 아무리 모아도 메인 캡차 FRR 은 안 고쳐진다.
8/03 에 드래그 단위 재학습이 실패한 것(10.3% · 22.0%)도 같은 이야기다.

## ③ 미지 family 최악 ASR — 실패

### 배제한 것

**임계값** — 약점셋은 정의상 모델이 사람이라 답한 점들이라 어떤 임계값 위에도 있다.
0.9 아래에서는 100% 다.

**재학습** — 7/22 에 이미 탈락. 봇 8.17% → 1.58% 인 대신 처음 보는 사람 FRR 이
2.39% → 9.06% 로 튀었다.

### 새로 시도한 것 — 모델 다양성

약점셋은 **모델 하나를 노려** 만들어졌다. 독립적으로 학습한 여러 모델을 동시에
만족시켜야 한다면 무너질 수 있다는 가설이다. 사람 FRR 을 0.95% 로 고정해 비교했다.

| 구성 | 사람 FRR | 약점셋 ASR | 외부 holdout ASR |
|---|---:|---:|---:|
| 단일 lgbm (기준선) | 0.95% | 72.0% | 14.2% |
| **lgbm 3중 (시드만)** | 0.95% | **58.0%** | 11.6% |
| lgbm+rf+et | 0.98% | 75.0% | 19.6% |
| lgbm+rf+et 2배 | 0.95% | 73.0% | 11.6% |

**시드 다양성이 가장 좋았고(72% → 58%), 다른 계열을 섞으면 오히려 나빠졌다.**
RandomForest·ExtraTrees 가 약점셋에도 사람에게도 후한 점수를 줘서, `min` 융합이
점수를 못 끌어내리고 임계값만 낮아진다.

14 포인트는 실재하는 개선이지만 **기준 10% 와는 멀다.**

### 남는 것은 기준 분리 제안 — 이건 팀 결정이다

```
미지 family ≤10%      비적응형만. 외부 holdout 3.6% · playwright 0%  →  통과
적응형 화이트박스      차단 기준이 아니라 비용 기준
                      · 모델 파일·점수 비공개
                      · 성공 1건당 질의 160회 이상 (약점셋 100개에 후보 16,000개)
                      · 레이트리밋·PoW 로 질의 단가 유지
```

**64% 는 화이트박스 숫자다.** 실제 공격자는 점수를 못 보고 통과/실패 1비트만 받으며
레이트리밋 2.5초와 PoW 를 문다. 16,000 회면 11시간 이상이다.

궤적 모델로 적응형 화이트박스 공격을 막는 것은 원리적으로 불가능하다 — 막을 수
있으면 그건 애초에 약점이 아니다.
