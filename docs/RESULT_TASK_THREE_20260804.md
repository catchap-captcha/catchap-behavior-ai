## ① 새 외부 holdout — 해결

### 이미 있었다

락박스 매니페스트에 **학습에도 락박스에도 안 들어간 참여자 7명**이 기록돼 있었다.
`previous_test_participants` 로 표시돼 있었고, 아무도 쓰지 않고 있었다.

검증한 것:

```
previous_test 참여자          7명 · 2,219행
development 참여자와 겹침      0명   (development 30명 · 15,802행)
직전 락박스 참여자와 겹침       0명
임계값 보정에 포함됐나          아니오
```

마지막 항목은 계산으로 확인했다. 보정에 쓰인 사람 행이 14,913 이고
`development 15,802 − 익명 889 = 14,913` 이다. 정확히 일치하므로 보정은 development
만 썼다.

**즉 현재 후보가 학습에서도 임계값 보정에서도 한 번도 못 본 사람 7명이다.**

## ② FRR (처음 보는 사람) — 부분 해결, 그리고 진단이 바뀌었다

같은 모델, 같은 임계값인데 표면에 따라 결과가 갈린다.

```
레거시 표면 · 처음 보는 사람 7명    FRR 0.68%   최악 2.17%
메인 캡차   · 처음 보는 사람 1명    FRR 4.5%
```

**"사람마다 달라서 일반화가 안 된다" 가 아니었다.** 처음 보는 사람 7명에서 0.68%면
사람 축으로는 잘 일반화한다. 문제는 **표면**이다.

이 진단 변경이 중요하다. 어제까지의 결론은 "사람이 부족하다" 였는데, 정확히는
**"메인 캡차 표면의 사람 데이터가 부족하다"** 이다. 레거시 사람을 아무리 더 모아도
메인 캡차 FRR 은 안 고쳐진다.

어제 드래그 단위 재학습이 실패한 것(10.3% · 22.0%)도 같은 이야기다. 메인 캡차
사람이 2명뿐이라 표면을 못 배웠다.

## ③ 미지 family 최악 ASR — 실패

### 배제한 것

**임계값** — 약점셋은 정의상 모델이 사람이라 답한 점들이라 어떤 임계값 위에도 있다.
0.9 아래에서는 100%다.

**재학습** — 7/22에 이미 탈락. 봇 8.17% → 1.58% 인 대신 처음 보는 사람 FRR 이
2.39% → 9.06% 로 튀었다.

### 새로 시도한 것 — 모델 다양성

약점셋은 **모델 하나를 노려** 만들어졌다. 독립적으로 학습한 여러 모델을 동시에
만족시켜야 한다면 무너질 수 있다는 가설이다. 사람 FRR 을 0.95% 로 고정하고 비교했다.

| 구성 | 사람 FRR | 약점셋 ASR | 외부 holdout ASR |
|---|---:|---:|---:|
| 단일 lgbm (기준선) | 0.95% | 72.0% | 14.2% |
| **lgbm 3중 (시드만)** | 0.95% | **58.0%** | 11.6% |
| lgbm+rf+et | 0.98% | 75.0% | 19.6% |
| lgbm+rf+et 2배 | 0.95% | 73.0% | 11.6% |

**같은 알고리즘의 시드 다양성이 가장 좋았고(72% → 58%), 다른 계열을 섞으면 오히려
나빠졌다.** RandomForest·ExtraTrees 가 약점셋에도 사람에게도 후한 점수를 줘서,
`min` 융합이 그 점수를 못 끌어내리고 임계값만 낮아진다.

14 포인트는 실재하는 개선이지만 **기준 10% 와는 거리가 멀다.**

### 그래서 남는 것은 기준 분리 제안뿐이다

이건 제가 혼자 정할 수 없다.

```
미지 family ≤10%      비적응형만. 외부 holdout 3.6% · playwright 0%  →  통과
적응형 화이트박스      차단 기준이 아니라 비용 기준
                      · 모델 파일·점수 비공개
                      · 성공 1건당 질의 160회 이상 (약점셋 100개에 후보 16,000개)
                      · 레이트리밋·PoW 로 질의 단가 유지
```

**64%는 화이트박스 숫자다.** 실제 공격자는 점수를 못 보고 통과/실패 1비트만 받으며,
레이트리밋 2.5초와 PoW 를 문다. 16,000회면 11시간 이상이다.

궤적 모델로 적응형 화이트박스 공격을 막는 것은 원리적으로 불가능하다 — 막을 수 있으면
그건 애초에 약점이 아니다.

### 지켜야 할 것

약점셋이 실전에서 재현되려면 **점수가 새어나가야** 한다.

- `BEHAVIOR_DEBUG_RESPONSE` 같은 디버그 플래그가 프로덕션에서 꺼져 있을 것
- **모델 파일 접근 통제.** 8/03 에 저장소에 커밋했으므로(`3dd2d72`) 저장소 권한이
  곧 모델 접근 권한이다. 이건 내가 만든 상황이니 확인이 필요하다
