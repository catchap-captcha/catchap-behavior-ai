## 0. 먼저 — 1절 정정은 제 잘못이 맞습니다

ORM 모델에 컬럼을 선언하면 **모드와 무관하게 모든 SELECT에 포함된다**는 지적이 정확합니다.
제가 "`off`면 컬럼 없이 배포해도 된다"고 쓴 건 틀렸습니다. 기능 플래그는 코드 경로만 끄지
ORM의 컬럼 목록을 바꾸지 않는데, 그걸 안전망처럼 서술했습니다.

DB 담당자가 컬럼을 미리 넣어두지 않았다면 하트비트·진도·체크포인트가 전부 1054로 실패해
인강 시청이 통째로 멈췄을 겁니다. **"DDL 먼저, 코드 나중"이 유일한 안전 순서**라는 일반화도
그대로 받아들입니다.

`alembic_version` 마커까지 정리해 주신 것 감사합니다.

## 1. 지적 2건 + 제가 만든 블로커 1건 → 고쳐서 올렸습니다

**브랜치**: `catchap-backend` `fix/escalation-record` (`04227c0`)
`origin/jy` 기준이라 충돌 없이 머지됩니다. **전체 375 passed, 1 skipped.**

### ① `record`가 캡차 설정을 요구하던 것 — 이게 지금 관측을 막고 있었습니다

`_escalation_mode()`가 `off`가 아닌 **모든** 모드에서 `MAIN_CAPTCHA_URL`/`SECRET`을
요구하도록 짜여 있었습니다. 그런데 **`record`는 캡차를 부르지 않습니다.** 신호를 누적하고
기록만 합니다.

임계값을 정하려면 관측이 먼저인데, 캡차 시크릿을 받기 전까지 아무것도 못 보는 상태를
제가 만들어 놓은 셈입니다. `enforce`만 요구하도록 좁혔습니다.

원래 의도(설정 누락 방지)는 유지됩니다 — 실제로 캡차를 부르는 건 `enforce`뿐이고
거기서는 여전히 강등합니다.

> **그래서 `record`는 김민서 님 시크릿 없이 지금 바로 켤 수 있습니다.**
> `BOT_ESCALATION_MODE=record` 하나면 됩니다.
> `MAIN_CAPTCHA_URL`/`MAIN_CAPTCHA_SITE_SECRET`은 `enforce`로 갈 때 받으시면 됩니다.

### ② 감쇠가 모드 게이팅 밖에 있던 것 (지적하신 대로입니다)

게이팅 안으로 옮겼습니다. `record`로 쌓은 값이 `off`로 내린 뒤 씻기지 않습니다.

테스트는 **실제 하트비트로** 검증합니다(`bot_suspicion=7` → `off` 전환 → 정상 전진
하트비트 → 값 유지). 게이팅을 도로 빼면 이 테스트가 실패하는 것까지 확인했습니다.
지적하신 대로 기존 `test_off_mode_is_completely_inert`는 이 경로를 못 봤습니다.

### ③ `bump_suspicion` 반환값 (지적하신 대로입니다)

**"변경했는가"를 `bool`로** 돌려주도록 바꿨습니다. `claim_session`의 커밋 조건이
그대로 읽힙니다. 상한 도달 시 `False`가 되어 말씀하신 불필요한 커밋도 사라집니다.
나머지 두 호출부는 반환값을 쓰지 않아 영향 없습니다.

## 2. 시험 자동화 방어 — 1~3 진행에 동의합니다

`course_exam_*`이 0행인 지금이 최적기라는 판단, 그리고 DDL이 필요 없다는 확인 모두
동의합니다. 결정 4건에 대한 답입니다.

### ① 쿨다운 — 10분 지지

매 사이클 미정복 문항의 25%가 정복되므로 `0.75ⁿ × 50 < 1` → 약 14사이클,
**2~3시간**입니다. (5분이면 1시간대, 30분이면 7시간)

한 가지 덧붙이면, **쿨다운의 힘은 문항 풀이 회차 크기보다 클 때 나옵니다.**
50문항/회차 10문항이면 공격자가 **첫 5회차를 대기 없이** 돌립니다. 그 구간은
쿨다운이 아니라 ②의 레이트리밋이 막아야 합니다. 둘이 같이 들어가야 의미가 있습니다.

### ② 문항당 최소 3초 — 동의하되, 방어로 기대하지 마세요

봇은 그냥 30초 자면 됩니다. **진짜 가치는 `solve_time_ms`를 서버 계산으로 바꾸는 쪽**입니다.
"근사가 아니라 신뢰할 수 없는 값"이라는 지적이 정확하고, 그게 바뀌면 나중에 봇 판별의
실제 입력 신호가 됩니다. 지금 값으로는 아무것도 못 합니다.

### ③ 시간당 20회차 — 동의

정상 학생은 50문항이면 5회차이니 4배 여유입니다. 그리고 위에서 말한
"첫 5회차 무료 구간"을 이게 막습니다.

### ④ `perfect` 모드 — 쿨다운 면제해도 됩니다

코드를 확인했습니다(`course_exam.py:1135`). **완벽 도전은 수료 후 전용이고 미수료 학생은
`perfect` 파라미터가 무시**됩니다. 그리고 전 문항을 한 회차에 다 맞혀야 하므로
무작위로는 `4⁻⁵⁰`, 사실상 불가능합니다.

**구조 자체가 자기제한적**이라 쿨다운 없이 레이트리밋만으로 충분합니다.
쿨다운을 걸면 정당한 재도전자만 불편해집니다.

## 3. 순서 하나만 — 4번(캡차 승급 연계)은 지금 붙이지 마세요

메인 캡차가 아직 배포 전이고, **현재 배포본은 오답 풀이를 AI에 보내지 않습니다.**
어제 실측했습니다:

```
캡차 통과(success=True)  → AI 도달 2/2
캡차 실패(success=False) → AI 도달 0/4
```

병합본(`ai-service` `sw-captcha` `e061df7`)은 정답 여부와 무관하게 채점하고 그걸
테스트로 고정해뒀지만, 아직 배포되지 않았습니다.

미완성 시스템 둘을 엮으면 문제가 생겼을 때 어느 쪽인지 분리가 안 됩니다.
**1~3 먼저 하고, 캡차 쪽이 정리되면 그때 붙이는 게 맞습니다.**
