# CatChap 행동 데이터 검증 기준과 현재 상태

기준일: 2026-07-22

## 문서 목적

이 문서는 CatChap의 마우스 궤적 기반 Bot 판별 모델을 학습, 비교, 후보 선정, 관찰 모드, 배포로 진행할 때 사용할 기준을 정리한다.

현재 실제 판정 기준의 기준점은 `training/run_local_training.py`다. 과거 문서 일부에 남은 "미지 Bot family Bot Recall 80%"는 이전 기준이다. 현재 코드의 기준은 **미지 Bot family 최악 ASR 10% 이하**, 즉 **Bot Recall 90% 이상**이다.

## 1. 용어와 계산식

### 1.1 Human FRR

Human False Rejection Rate. 정상 사용자를 Bot으로 잘못 차단한 비율이다.

```text
Human FRR = 정상 Human 중 Bot으로 판정된 수 / 전체 정상 Human 수
```

FRR이 높으면 실제 사용자가 CAPTCHA를 풀었는데도 차단되므로 사용성 문제가 생긴다. 보안 모델 비교에서 Accuracy보다 먼저 제한하는 이유다.

### 1.2 Bot Recall과 Bot ASR

Bot Recall은 전체 Bot 중 차단한 비율이다. Bot ASR은 Bot이 Human으로 통과한 비율이다.

```text
Bot Recall = 차단된 Bot 수 / 전체 Bot 수
Bot ASR = 통과한 Bot 수 / 전체 Bot 수 = 1 - Bot Recall
```

예를 들어 Bot 1,000개 중 60개가 통과하면 ASR은 6%다.

### 1.3 알려진 Bot과 미지 Bot family

- 알려진 Bot: 학습에 사용한 Bot family의 test 분할이다. 학습 분포 안에서의 기본 방어력을 본다.
- 미지 Bot family: 특정 family 전체를 학습에서 제외한 뒤 평가한다. 처음 보는 공격 방식으로 일반화되는지를 본다.
- 외부 holdout: Playwright, VAE처럼 학습 데이터와 분리해 둔 별도 Bot 데이터다. 학습이나 임계값 보정에는 절대 사용하지 않고 점수만 측정한다.

## 2. 현재 데이터와 준비 기준

### 2.1 현재 보유 데이터

| 항목 | 현재 수량 | 설명 |
|---|---:|---|
| Human 궤적 | 20,066건 | 읽기 전용 DB 스냅샷에서 품질 정제한 Human 시도 |
| 연결된 Human 참여자 | 46명 | 사람 단위 분할이 가능한 참여자 수 |
| 익명 확인 Human | 889건 | 참여자 ID가 없어 train 전용으로 사용 |
| 개발용 Bot | 13,300건 | 13개 family의 규칙형, PCA-GMM, replay, 브라우저 Bot 등 |
| Feature schema 2.3 | 전체 55개, 궤적 전용 50개 | 이번 검증은 궤적 전용 feature를 사용 |

### 2.2 학습 시작 최소 기준

| 항목 | 최소 기준 | 현재 상태 |
|---|---:|---|
| Human 데이터 | 500건 | 통과 |
| Bot 데이터 | 500건 | 통과 |
| 연결된 Human 참여자 | hard gate 없음 | 현재 46명, 분할 품질 참고 정보 |
| Bot family | 3종 | 통과, 현재 13종 |

연결된 Human 참여자 수는 hard gate가 아니다. 다만 사람 단위 train, validation, test 분할을 만들려면 기술적으로 최소 3개의 연결된 참여자 그룹이 필요하다. 이 기준을 통과했다고 배포 가능한 것은 아니다.

### 2.3 데이터 무결성 기준

학습 전에 아래 조건을 확인한다.

1. 모든 행에 `label`과 `label_source`가 있어야 한다.
2. Human과 Bot의 label이 명확해야 한다.
3. 같은 feature schema version만 한 학습에 사용해야 한다.
4. 모델 입력 feature에 NULL, NaN, Infinity가 없어야 한다.
5. attempt ID 중복, 누락된 원본 이벤트, 포인트 수 부족 궤적을 점검한다.
6. Human과 Bot의 클래스 비율을 확인한다. 불균형이 심하면 class weight를 적용한다.
7. 외부 holdout은 manifest에서 `external_holdout_only`로 표시하고 학습 입력에서 차단한다.

## 3. 데이터 분할과 임계값 보정

### 3.1 누수 방지 분할

동일한 사람이 train과 test에 동시에 있으면 모델이 그 사람의 습관을 외워 성능이 과대평가될 수 있다. 이를 막기 위해 다음 규칙을 사용한다.

| 데이터 | 분할 규칙 |
|---|---|
| 연결된 Human | 동일 참여자의 모든 시도를 하나의 split에만 배치 |
| 익명 확인 Human | 참여자 단위 누수가 확인되지 않으므로 train 전용 |
| 규칙형 Bot | family별 생성 배치 그룹 단위로 train, validation, test 분리 |
| GAN 계열 Bot | 원본 Human 참여자와 같은 split으로 배치 |

연결된 그룹은 대략 train 70%, validation 15%, test 15% 비율로 나눈다. 행 수는 참여자별 시도 횟수가 달라 정확히 70:15:15가 아닐 수 있다.

### 3.2 임계값 보정

모델은 Human일 확률 `P(Human)`을 출력한다. 이 점수가 임계값보다 낮으면 Bot으로 판정한다.

1. 개발 데이터에서 사용자와 Bot 그룹 기준 5-fold OOF 교차검증을 수행한다.
2. 각 fold의 Human FRR이 제한을 지키는 임계값 후보만 남긴다.
3. 남은 후보 중 Bot Recall이 가장 높은 공통 임계값을 선택한다.
4. test는 임계값을 고르는 데 사용하지 않고, 최종 평가에 한 번만 사용한다.

2.3의 현재 결과는 실행 환경 제한 때문에 120-tree LightGBM과 validation split 임계값을 쓴 스모크 검증이다. 정식 5-fold OOF 결과가 아니다.

## 4. 성능 통과 기준

### 4.1 실험 후보 기준

| 항목 | 통과 기준 | 의미 |
|---|---:|---|
| Human FRR | 일반 test와 모든 family holdout에서 3% 이하 | 정상 사용자를 과도하게 막지 않음 |
| 알려진 Bot ASR | 일반 test에서 5% 이하 | 학습 분포 안의 Bot 기본 방어력 |
| 미지 family 최악 ASR | 모든 family holdout과 외부 holdout 중 최악값 10% 이하 | 처음 보는 공격 방식 일반화 성능 |
| `replay_warp` ASR | 5% 이하 | 재생 공격에 대한 별도 강화 기준 |

실험 후보는 위 기준을 모두 만족해야 한다. 하나라도 실패하면 candidate 파일만 보관하고 production에는 올리지 않는다.

### 4.2 Observation mode 기준

Observation mode는 차단을 하지 않고 위험 점수와 실제 판정 결과를 기록해 보는 단계다.

| 항목 | 기준 |
|---|---:|
| 일반 test Human FRR | 3% 이하 |
| 실제 차단 | 하지 않음 |

### 4.3 Shadow mode 기준

Shadow mode는 실제 서비스 요청에서 판정은 수행하되 차단 결과를 서비스 동작에 적용하지 않고 비교하는 단계다.

| 항목 | 기준 |
|---|---:|
| 실험 후보 기준 | 모두 통과 |
| 일반 test Human FRR | 3% 이하 |
| 새 외부 holdout | 반드시 존재 |
| 새 외부 holdout ASR | 5% 이하 |

새 외부 holdout은 이미 개발과 튜닝에 사용한 데이터가 아니라, 새 참여자 또는 새 수집 시점에서 분리한 데이터여야 한다.

### 4.4 Production 승격 기준

Production으로 올리려면 Shadow mode 조건을 모두 만족하고, 일반 test Human FRR이 더 엄격한 **1% 이하**여야 한다.

```text
Production = Shadow mode 통과 + 일반 test Human FRR <= 1%
```

연결된 Human 참여자 수는 사람 단위 분할 가능 여부를 판단하는 품질 정보로 기록한다. Observation, Shadow mode, Production의 통과 조건으로는 사용하지 않는다.

## 5. Bot 검증 종류

### 5.1 일반 test

학습에 사용한 family가 train, validation, test로 나뉜 상태에서 test를 평가한다. 알려진 Bot ASR과 기본 Human FRR을 확인한다.

### 5.2 Family holdout

한 Bot family를 통째로 train과 validation에서 뺀다. 남은 family와 Human만으로 학습한 뒤, 제외한 family와 Human test를 평가한다.

현재 주요 family 예시:

- `straight`: 직선 이동
- `accel`: 일정 가속 이동
- `jitter`: 인위적 흔들림 추가
- `bezier_curve`: 베지어 곡선 이동
- `stop_go`: 멈춤과 이동 반복
- `overshoot_correct`: 목표를 넘긴 뒤 보정
- `waypoint`: 중간 지점 경유
- `random_timing`: 무작위 시간 간격
- `frame_quantized`: 프레임 단위 시간 양자화
- `pca_gmm_surrogate`: PCA-GMM 기반 ML 생성 Bot
- `replay_warp`, `replay_adversarial`: 재생 공격 변형

### 5.3 외부 holdout

외부 holdout은 detector 학습과 임계값 조정에 넣지 않는다. 현재 예시는 Playwright 브라우저 Bot과 VAE 생성 Bot이다.

VAE는 팀의 약점을 찾는 레드팀용 생성기다. 외부 holdout VAE 결과가 나빠도 VAE 표본을 detector 학습 데이터에 넣어 수치를 맞추지 않는다.

### 5.4 최종 결합 검증

모델 단독 점수만으로 끝내지 않고, 실제 CAPTCHA 연결 후 아래 신호를 결합한 최종 FRR과 ASR을 다시 측정한다.

- ML 모델의 `P(Human)` 점수
- Trace Fingerprint
- DTW 기반 궤적 유사도
- 세션 요청 빈도
- 서버 nonce와 challenge, 세션 바인딩 결과

이 문서의 2.3 결과는 주로 궤적 ML feature view 결합의 오프라인 결과다. API에서 위 모든 신호가 실시간으로 결합된 최종 서비스 결과는 별도 검증이 필요하다.

## 6. 후보 모델 비교와 선택

정식 파이프라인은 다음 4개 모델을 같은 데이터와 split으로 비교한다.

1. Random Forest
2. Extra Trees
3. XGBoost
4. LightGBM

먼저 Human FRR 제한을 통과한 모델만 후보로 남긴다. 보안 게이트까지 통과한 후보는 다음 순서로 우선순위를 정한다.

1. 미지 family 최악 ASR이 낮은 모델
2. 알려진 Bot ASR이 낮은 모델
3. 평균 Bot Recall이 높은 모델
4. Human F1이 높은 모델
5. 평균 추론 시간이 빠른 모델

Accuracy는 참고 지표일 뿐 최종 선택 기준이 아니다. 다음 값도 보고서에 기록한다.

- Human Precision, Recall, F1
- Bot Recall과 Bot ASR
- ROC-AUC, PR-AUC
- 혼동행렬
- 평균 추론 시간
- Feature Importance

## 7. Feature Schema 2.3

Schema 2.3은 전체 55개 feature, 궤적 전용 50개 feature를 사용한다. 기존 속도, 가속도, jerk, 방향 전환, 시간 간격, 공간 분포, speed burst, 시간 보간 신호에 다음 물리 일관성 신호를 추가했다.

| 추가 feature | 설명 |
|---|---|
| `speed_turn_abs_correlation` | 회전 크기와 다음 구간 속도의 관계. 사람이 방향을 크게 바꿀 때 감속하는 경향을 본다. |
| `turn_change_smoothness` | 연속된 회전 크기가 얼마나 급격히 달라지는지 본다. |
| `pause_position_entropy` | 긴 멈춤이 경로의 한 위치에만 몰리는지, 여러 위치에 자연스럽게 분포하는지 본다. |

`speed_turn_abs_correlation`의 인덱스 매칭 오류를 수정한 뒤 사람 20,066건과 개발 Bot 13,300건의 해당 feature를 다시 계산했다.

## 8. 2.3 스모크 검증 구조

### 8.1 두 feature view 결합

단일 feature 조합은 PCA-GMM과 stop-go에 서로 다른 장단점을 보였다. 그래서 다음 두 LightGBM view를 보수적으로 결합해 확인했다.

- View A: 시간·형태 중심의 feature view, 속도-회전 상관관계는 제외한 ablation view
- View B: 속도-회전 상관관계를 포함한 수정된 2.3 view
- 모델: 각 view마다 120-tree LightGBM
- 결합 점수: `min(P(Human)_A, P(Human)_B)`
- 의미: 두 view 중 하나라도 Bot이라고 강하게 의심하면 최종 Human 점수를 낮춘다.
- 임계값: validation split에서 Human FRR 3% 이하 조건으로 보정

이 방식은 정식 production 구조가 아니라, 미지 family 약점 보완 가능성을 보기 위한 오프라인 스모크 검증이다.

### 8.2 결과

| 검증 대상 | 표본 구성 | Bot ASR | Human FRR | 기준 판정 |
|---|---|---:|---:|---|
| 일반 test, 알려진 Bot | Bot 2,251 + Human 2,219 | 8.0%, Bot 181건 통과 | 0.32%, Human 7건 차단 | ASR 5% 기준 미달 |
| PCA-GMM 미지 family | 학습 제외 Bot 1,000 + Human 2,219 | 6.4%, Bot 64건 통과 | 0.09%, Human 2건 차단 | 미지 family 10% 기준 통과 |
| stop-go 미지 family | 학습 제외 Bot 1,000 + Human 2,219 | 6.1%, Bot 61건 통과 | 0.27%, Human 6건 차단 | 미지 family 10% 기준 통과 |
| 새 VAE 외부 holdout | 학습 미사용 Bot 1,000 | 0.6%, Bot 6건 통과 | Human 표본 없음 | 외부 Bot ASR 5% 기준 통과 |

### 8.3 해석

- PCA-GMM과 stop-go는 각각 학습에서 완전히 제외한 뒤 평가했으므로, 미지 family 일반화 여부를 확인하는 결과다.
- VAE 1,000건은 학습과 임계값 보정에 넣지 않은 외부 holdout이다.
- VAE 외부 holdout에는 Human이 없으므로 이 파일만으로 Human FRR은 계산할 수 없다. Human FRR은 같은 시점의 별도 Human holdout으로 다시 확인해야 한다.
- 일반 test 알려진 Bot ASR이 8.0%이므로, 현재 2.3 결합 모델은 실험 후보의 알려진 Bot ASR 5% 기준을 통과하지 못했다.
- 따라서 현재 결과만으로 candidate 확정, Shadow mode, Production 승격을 해서는 안 된다.

### 8.4 정식 4모델 OOF 검증 결과

스모크 검증 다음에는 수정된 schema 2.3 feature를 고정하고 Random Forest, Extra Trees, XGBoost, LightGBM을 각각 300-tree 설정으로 다시 검증했다.

- 사용자와 Bot 그룹 기반 5-fold OOF로 임계값을 보정했다.
- 동일한 untouched test를 사용했다.
- `replay_adversarial`, `replay_warp`을 제외한 11개 Bot family를 하나씩 학습에서 완전히 제외했다.
- Playwright 100건과 VAE 1,000건 외부 holdout을 학습 없이 채점했다.

| 모델 | OOF FRR | Test FRR | 알려진 Bot ASR | 최악 미지 ASR | 최악 외부 ASR | 결과 |
|---|---:|---:|---:|---:|---:|---|
| LightGBM | 0.81% | 0.05% | 8.53% | 38.80% | 4.30% | 알려진 Bot, 미지 family 기준 실패 |
| Extra Trees | 1.80% | 1.13% | 8.71% | 98.80% | 22.60% | 알려진 Bot, 미지 family, VAE 기준 실패 |
| XGBoost | 0.81% | 0.00% | 8.44% | 70.10% | 4.10% | 알려진 Bot, 미지 family 기준 실패 |
| Random Forest | 1.20% | 0.18% | 8.17% | 33.30% | 0.40% | 알려진 Bot, 미지 family 기준 실패 |

정식 결과에서 PCA-GMM과 stop-go가 특히 약점이었다. 따라서 이전 120-tree 두-view 스모크 결과는 가능성 확인용으로만 해석해야 하며, 단일 정식 모델을 production에 올릴 근거가 되지 않는다.

### 8.5 정식 두-view 결합 검증 결과

수정 완료된 schema 2.3 데이터에서 두 input view를 명시적으로 분리해 다시 검증했다.

- 일반 view: 물리 feature 3개를 제외한 47개 궤적 feature
- dynamics/physics view: 속도, 가속, 회전, 정지, timing 및 물리 feature를 중심으로 한 41개 feature
- 점수 결합: `min(P_human_general, P_human_dynamics)`
- 두 view 모두 같은 개발용 Human/Bot 행만 학습했다. PCA-GMM, VAE, Playwright 외부 holdout은 학습 또는 threshold 보정에 넣지 않았다.
- 사용자·Bot 그룹 기반 5-fold OOF로 하나의 threshold를 고정하고, untouched test와 replay를 제외한 11개 family를 채점했다.

| 항목 | 결과 | 판정 |
|---|---:|---|
| OOF Human FRR | 1.06% | 통과 |
| 일반 test Human FRR | 0.05% | 통과 |
| 일반 test 알려진 Bot ASR | 8.17% | 5% 기준 실패 |
| 최악 미지 family ASR | stop-go 20.90% | 10% 기준 실패 |
| PCA-GMM ASR | 19.70% | 10% 기준 실패 |
| random-timing ASR | 11.90% | 10% 기준 실패 |
| 외부 Playwright ASR | 0.00% | 통과 |
| 새 VAE 외부 ASR | 1.70% | 통과 |

두-view 결합은 Human FRR과 VAE 외부 holdout에는 문제가 없었지만, 알려진 Bot과 stop-go/PCA-GMM 일반화 기준을 충족하지 못했다. 따라서 이 모델도 candidate로만 보관하며 API 차단 모드나 배포 후보로 승격하지 않는다.

### 8.6 Hard-negative 가중 검증 결과

두-view 기본 모델에서 개발용 Bot 중 사람으로 통과한 어려운 사례를 더 강하게 학습하는 실험을 추가했다. 가중치 `3배`는 test를 보기 전에 고정했다.

- 각 outer OOF fold의 train에서만 4-fold inner 그룹 OOF를 수행했다.
- inner OOF의 Human-safe threshold를 통과한 개발용 Bot만 hard negative로 표시했다.
- VAE, Playwright, PCA-GMM family holdout, stop-go family holdout, untouched test는 hard-negative 표시나 가중치 산정에 사용하지 않았다.
- 최종 개발용 재학습에서 hard negative Bot 782건이 3배 가중됐다.

| 항목 | 결과 | 판정 |
|---|---:|---|
| OOF Human FRR | 2.39% | 3% 기준 통과 |
| OOF 알려진 Bot ASR | 1.58% | 5% 기준 통과 |
| untouched test Human FRR | 9.06% | 3% 기준 실패 |
| untouched test 알려진 Bot ASR | 6.04% | 5% 기준 실패 |

OOF에서 좋아 보였더라도 untouched test Human FRR이 9.06%로 급등했기 때문에 정상 사용자를 과도하게 막는 후보이다. 이 후보는 즉시 탈락이며, Human FRR hard gate에서 이미 실패했으므로 family holdout과 외부 Bot holdout은 추가 채점하지 않았다. 같은 test를 보고 가중치나 threshold를 재조정하면 검증 오염이 되므로, 다음 구조 변경은 개발 데이터 내부 nested OOF로만 고정한 뒤 새로 분리한 Human holdout에서 한 번 평가한다.

### 8.7 재예약 Lockbox baseline 검증

기존 test를 다시 사용하지 않기 위해, 기존 snapshot에서 다음 재예약 lockbox를 만들었다. 이는 새로 수집한 독립 데이터가 아니라는 한계를 가진 내부 holdout이다.

- 이전 test Human 참여자 7명, 2,219건은 다음 development에서 제외했다.
- 이전 train Human 참여자 중 해시로 고정한 10명, 2,045건을 새 Human lockbox로 분리했다.
- replay 두 family는 현재 요청에 따라 제외했다.
- non-replay Bot에서 이전 test batch 1,731건을 제외하고, family별 이전 train batch 하나씩 총 824건을 새 Bot lockbox로 분리했다.
- 남은 Human 15,802건과 Bot 7,745건만으로 기본 two-view 후보를 OOF 보정하고 학습했다.

| 항목 | 결과 | 판정 |
|---|---:|---|
| Human lockbox FRR | 6.31% (129 / 2,045) | 3% 기준 실패 |
| Bot lockbox ASR | 0.00% (0 / 824) | 5% 기준 통과 |

Human lockbox FRR이 6.31%이므로 baseline 후보는 탈락이다. family holdout과 외부 Bot holdout은 추가 채점하지 않았다. Human/Bot lockbox 모두 사용 완료로 표시했으며, 같은 lockbox로 다음 후보의 threshold나 feature를 다시 조정하지 않는다.

## 10. 다음 정식 검증 순서

1. 기존 untouched test와 재예약 Human/Bot lockbox를 모두 고정한다. 이 파일들은 threshold, feature, 가중치 선택과 재채점에 사용하지 않는다.
2. 다음 후보는 개발 데이터 내부 nested OOF만으로 구조와 가중치를 확정한다. VAE, PCA-GMM, stop-go, Playwright 외부 holdout은 계속 학습과 선택에 넣지 않는다.
3. 다음 후보를 최종 판단하려면 새로 수집하거나 아직 사용하지 않은 Human holdout이 필요하다. Human FRR 3% 이하를 먼저 확인한다.
4. Human gate를 통과한 후보만 새 known-Bot holdout의 ASR 5% 이하를 확인하고, 그 다음 replay를 제외한 11개 family holdout에서 최악 ASR 10% 이하를 확인한다.
5. CAPTCHA 흐름이 완성되면 `replay_warp`, nonce, challenge, 세션 바인딩을 포함한 최종 방어도를 검증한다.
6. 모든 실험 후보 기준을 통과한 모델만 Observation mode를 검토한다.
7. 새 외부 Human과 Bot holdout을 확보해 Shadow mode와 Production 승격을 검토한다.
