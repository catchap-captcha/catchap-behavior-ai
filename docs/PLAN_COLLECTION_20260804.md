# 수집 설계 — 시작 전에 정해 둔다

조성원 · 2026-08-04 · **수집 전에 확정. 결과를 보고 고치지 않는다.**

---

## 왜 지금 정하나

레거시 사람 데이터가 오늘부로 **전부 배정됐다.**

```
15,802   학습에 씀
 2,045   직전 락박스 — 소진
 2,219   previous_test — 8/04 소진
────────
20,066   남은 것 0
```

**앞으로 어떤 후보를 만들어도 사람으로 검증할 데이터가 없다.** 이번 수집이 그것을
만드는 유일한 기회이고, 결과를 보고 나눈 홀드아웃은 홀드아웃이 아니다.

그래서 나누는 규칙을 **명단이 정해지기 전에** 코드로 고정했다.

---

## 1. 참여자 코드

```
사람-장치      예: jy-mouse · jy-trackpad · ms-mouse
```

- **사람 이름은 사람마다 유일해야 한다.** `sw-mouse` 와 `sw-mouse-v2` 처럼 날짜를
  붙이면 8/03 에 내가 저지른 것처럼 같은 사람을 두 사람으로 세게 된다
- **장치는 접미사로만 구분한다.** 사람 단위 분리가 장치 때문에 깨지면 안 된다
- 개인정보는 받지 않는다. 이 코드가 저장되는 전부다

---

## 2. 목표

| | 값 | 근거 |
|---|---|---|
| 참여자 | **8명 이상** | 8/03 측정 — 2명으로 재학습하면 처음 보는 사람 오탐 10~22% |
| 1인당 세션 | 장치별 **40건 이상**, 60건 권장 | 아래 |
| 장치 | 사람마다 마우스 + 트랙패드 | 트랙패드·터치 표본이 0 |
| 소요 | 1인 30분 | 8/03 실측 21분에 95건 |

**세션 수를 사람마다 맞춘다.** 지금 데이터가 `sw` 156건 · `데모` 50건으로 3배
차이인데, 이러면 전체 평균이 한 사람 쪽으로 끌려간다. 40건은 참여자별 FRR 을
±3% 안에서 재기 위한 하한이다.

**터치는 이번 창에서 제외한다.** 폰은 터널을 못 쓰고, 그 결정은 8/03 에 내려졌다.
그러면 터치 사용자에 대해서는 아무 근거가 없다는 것을 승급 문서에 적는다.

## 3. 분리 규칙 — 재량이 없다

```
sha256("catchap-collection-split-20260804" + ":" + 사람이름)
  → 오름차순 정렬 → 앞에서 N 명이 봉인(평가용)
```

소금값은 **명단이 존재하기 전인 오늘 고정**했고 버전 관리에 들어 있다. 나중에
바꾸면 diff 에 남는다.

```bash
.venv/bin/python tools/collection_split.py jy-mouse jy-trackpad ms-mouse ... --holdout 3 \
  --write reports/collection_split_<날짜>.json
```

**누가 돌려도 같은 답이 나온다.** 나도 고를 수 없다.

| 인원 | 학습 | 봉인 |
|---:|---:|---:|
| 8명 | 5명 | 3명 |
| 10명 | 7명 | 3명 |
| 12명 이상 | 나머지 | 3~4명 |

봉인 3명이 하한이다. 2명이면 참여자별 최악값이 한 사람에 좌우된다.

## 4. 수집 창 규칙

- **한 창에서 다 같이 한다.** 서버 상태·문항 풀·배포본이 고정돼야 비교가 깨끗하다
- **창이 열린 동안 프론트·캡차 배포를 멈춘다.** 8/03 에 번들 해시가 하루에 두 번
  바뀌었다. 창을 나눠야 하면 참여자 코드에 창 번호를 붙인다
- **시작 시각에 배포본 해시를 기록한다.** 번들 파일명과 모델 버전
- 봇 대조군을 같은 창에서 돌린다 (민서 5종×20, 내 Playwright 3종×20)

---

## 5. 라벨과 품질

- 수집 직후 `label='human'`, `label_source='collection_<날짜>'` 를 붙인다.
  8/03 수집분이 라벨 없이 남아 분석에서 빠졌던 일을 반복하지 않는다
- **틀린 답도 버리지 않는다.** 정답 여부는 행동과 별개다
- 품질 거부(`duplicate_timestamps` 등)는 **버리지 말고 사유와 함께 남긴다.**
  7/31 에 사람 4건이 이 사유로 거부됐는데, 빠른 움직임에서는 정상이다

## 6. 판정 기준 — 7/30 에 확정한 것을 그대로 쓴다

```
전체 Human FRR ≤ 2%
최악 참여자 FRR ≤ 5%
사람 5명 전원
조건 그룹 ≥ 12
```

문서 기준(`docs/행동데이터_검증기준_현재.md`)과 함께 본다.

```
실험 후보     FRR ≤3% (모든 family holdout 포함) · 알려진 Bot ASR ≤5%
              미지 family 최악 ASR ≤10%
Shadow        + 새 외부 holdout 존재 · 그 ASR ≤5%
Production    + FRR ≤1%
```

**숫자를 보고 기준을 고치지 않는다.** 7/30 에 그렇게 정했고 7/31 에 33.3% 를 보고도
안 고쳤다.

## 7. 미리 적어두는 것 — 실패했을 때

이번 수집으로도 승급이 안 될 가능성이 크다. **미지 family 최악 ASR** 항목은
사람을 모아도 안 풀린다(8/04 에 세 가지 접근으로 확인, 64% → 약 45%).

그 경우 할 일은 정해져 있다.

1. **행동 모델은 `shadow` 유지.** 차단하지 않는다
2. **step-up 승급만 진행.** 오탐의 대가가 "차단" 이 아니라 "문제 한 번 더" 가 된다
3. **기준 분리를 팀에 올린다** — 비적응형 미지 family 와 적응형 화이트박스 공격은
   같은 칸에 넣을 수 없다

**이것도 결과다.** 3주 동안 무엇이 되고 무엇이 안 되는지를 측정으로 확정한 것이고,
"해봤더니 안 됐다" 와 "왜 안 되는지 안다" 는 다르다.
