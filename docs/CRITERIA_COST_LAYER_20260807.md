# 승급 기준 v2 — 비용을 올리는 층으로서

조성원 · 2026-08-07 · **결과를 보기 전에 고정한다** (단서는 0장)

---

## 0. 먼저 — 이 문서는 깨끗한 사전 등록이 아니다

정직하게 적는다. 이 기준을 쓰는 시점에 나는 이미 다음 숫자를 알고 있다.

```
playwright_ease_burst  ASR  0.0%
vae_bots               ASR 11.8%
ml_pca_gmm             ASR 25.2%
진화 탐색 회피율            73.7%
```

**그래서 "통과하는 값"을 고르지 않기 위한 규칙을 스스로 건다.**

```
1  모든 기준값은 위협 모델로 정당화한다. "지금 이 값이 나오니까" 는 근거가 아니다
2  이미 잰 계열의 기준은 현재값보다 엄격하게만 잡는다
3  최종 판정은 아직 한 번도 안 연 봉인(sw·ms 245건)에서 한다
4  이 문서를 고치면 고친 날짜와 이유를 남긴다
```

v1(`SECURITY_ACCEPTANCE_CRITERIA.md`)은 폐기하지 않는다. **목표가 달라서 기준이 달라지는 것**이지 v1이 틀려서가 아니다.

## 1. 무엇을 만드는 층인가 — 목표를 바꾼다

**v1의 전제**: 행동으로 봇을 가려낸다. 미지 공격 최악 ASR ≤10%.

**v2의 전제**: 행동으로 **공격 비용을 올린다.**

이유는 원리적이다. 사람 대행 서비스는 진짜 사람이 푼다. 행동 판별로 원리적으로
못 잡는다. 그러면 "봇을 다 막는다" 는 애초에 도달 불가능한 목표이고, 그 목표로
기준을 세우면 **영원히 승급 불가**가 된다. 실제로 그렇게 됐다.

도달 가능한 목표는 이것이다.

```
싼 공격은 막는다        Playwright 몇 줄 · 좌표 직접 주입 · 단순 보간
비싼 공격만 남긴다      우리 데이터 분포를 알아내 궤적 생성기를 만들거나
                       건당 돈을 내고 사람을 쓰거나
```

**공격자가 남는 길이 "돈이 드는 길" 뿐이면 이 층은 제 몫을 한 것이다.**

## 2. 위협 등급 — 무엇을 막을 의무가 있나

인강 사이트 자동화 7종 중 이 층의 사정거리 안에 있는 것만 적는다.

| 등급 | 공격 | 이 층의 의무 | 근거 |
|---|---|---|---|
| **A** | 브라우저 자동화 (Playwright·Selenium·Puppeteer) | **막는다** | 진입 비용이 거의 0. 튜토리얼로 가능. 실제 부정행위의 주 형태 |
| **A** | 좌표 직접 주입 / HTTP 재생 | **막는다** | 브라우저조차 안 띄운다. 가장 싼 공격 |
| **B** | 궤적 합성 (VAE·PCA-GMM 등) | **비싸게 만든다** | 우리 사람 데이터 분포를 알아내야 만든다. 공격자가 그 데이터를 못 가진다 |
| **B** | 재생 변형 (시간·크기·회전 와핑) | **비싸게 만든다** | 진짜 궤적을 먼저 확보해야 한다 |
| **C** | 적대적 최적화 (우리 모델을 직접 공격) | **범위 밖 — 측정만** | 모델 가중치나 점수 피드백이 필요하다. 그걸 가진 공격자는 이미 내부자다 |
| **C** | 사람 대행 서비스 | **범위 밖 — 원리적으로 불가** | 진짜 사람이 푼다. 비용은 오르지만 행동으로는 못 가른다 |

**A는 실패하면 승급 불가. B는 목표치를 두되 초과분은 잔존 위험으로 보고. C는 기준에서 뺀다.**

C를 빼는 것이 이 문서의 가장 큰 변경이다. 정당화는 이렇다 — 진화 탐색은 모델에
무제한 질의하며 정책을 최적화한다. 실제 공격자는 통과/실패만 볼 수 있고, 그것도
레이트리밋과 쿨다운에 걸린다. **73.7% 는 "모델을 손에 넣은 공격자" 의 상한이지
바깥 공격자의 상한이 아니다.**

## 3. 승급 기준

### 3.1 A등급 — 실패하면 승급 없음

| 항목 | 기준 | 측정 |
|---|---|---|
| 브라우저 자동화 ASR | **≤5%** | `playwright_bots_300` · `playwright_ease_burst_external_100` (미사용 봉인) |
| 좌표 직접 주입 ASR | **≤1%** | `rule_bots` · 직선/등속 계열 |
| 정확히 같은 궤적 재생 ASR | **≤1%** | 재생 도구 1,000건 |

**≤5% 의 근거**: 이 공격은 스무 줄이면 만들어진다. 스무 줄에 20번 중 1번 이상을
내주면 막는다고 할 수 없다. 현재 측정값(0.0%)보다 엄격한 값을 일부러 고르지 않은
이유는, 봉인·미사용 홀드아웃에서는 더 나쁠 수 있기 때문이다.

### 3.2 B등급 — 목표치. 초과분은 잔존 위험으로 명시

| 항목 | 목표 | 측정 |
|---|---|---|
| 궤적 합성 최악 ASR | **≤15%** | leave-one-family-out (`vae_bots` · `ml_pca_gmm`) |
| 재생 변형 ASR | **≤10%** | `replay_warp_external_1000` (미사용 봉인) |

**≤15% 의 근거**: 현재 최악이 25.2%(`ml_pca_gmm`)다. 규칙 2에 따라 현재값보다
엄격하게 잡는다. 15% 는 "여섯 번에 한 번" 이고, 그 정도면 공격자가 궤적 생성기를
만들고도 여섯 번을 시도해야 한다는 뜻이다. **여기에 쿨다운과 레이트리밋이 곱해진다.**

이 값을 못 넘으면 승급은 하되 **잔존 위험에 수치를 명시**한다. A등급과 달리
거부 사유가 아니다.

### 3.3 사용자 쪽 — v1 그대로 유지

| 항목 | 기준 |
|---|---|
| 전체 사람 오탐 | **≤2%** |
| 최악 참여자 오탐 | **≤5%** |
| 검증 참여자 | **5명** |

**여기는 완화하지 않는다.** 공격자 기준은 목표가 바뀌어 달라지지만, 사용자를 막는
비용은 목표와 무관하다. 오탐 하나가 강의를 못 듣는 학생 하나다.

### 3.4 측정 규약 — 오늘 얻은 것을 규칙으로 박는다

```
1  회피율과 오탐은 반드시 같은 동작점에서 잰다
   (calibrate_common_point.py 를 거치지 않은 두 숫자를 나란히 적지 않는다)

2  동작점은 모델이 학습에서 못 본 사람에게서 잡는다

3  공격 기반 궤적도 모델이 학습에서 못 본 것을 쓴다

4  미지 계열은 leave-one-family-out 으로만 잰다. 같은 생성기의 시드 분할은 안 된다

5  세대가 있는 탐색은 수렴을 확인하고 마지막 5세대 평균을 쓴다

6  숫자를 문서로 옮길 때 어느 조건에서 잰 값인지 같이 적는다
```

**6개 전부 2026-08-06 에 실제로 어겨서 숫자가 뒤집힌 항목이다.**

## 4. 판정 절차

```
1  학습 — 봉인(sw·ms) 과 미사용 홀드아웃을 뺀 데이터로만
2  동작점 — 학습에 안 쓴 사람에게서 오탐 2% 로 고정
3  A등급 채점 — 미사용 봉인 홀드아웃으로
4  B등급 채점 — leave-one-family-out
5  사람 오탐 — 봉인(sw·ms 245건) 한 번만 채점        ← 되돌릴 수 없다
6  판정
```

**5번 전에 1~4가 전부 끝나 있어야 한다.** 봉인은 한 번뿐이다.

## 5. 이 기준으로 승급하면 무엇을 말할 수 있나

```
말할 수 있는 것
  · 브라우저 자동화는 막는다 (실제 부정행위의 주 형태)
  · 뚫으려면 궤적 생성기를 만들거나 사람을 사야 한다 — 둘 다 비용이 든다
  · 사용자 오탐은 2% 이하다

말할 수 없는 것
  · "봇을 막는다"                    → 사람 대행은 원리적으로 못 막는다
  · "모델을 아는 공격자도 막는다"      → 73.7%. 잔존 위험으로 명시한다
  · "행동만으로 충분하다"             → PoW·레이트리밋·허니팟과 같이 쓰는 층이다
```
