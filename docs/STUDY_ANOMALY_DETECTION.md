# 이상 행동을 어떻게 잡나 — 자세히

조성원 · 2026-08-05

> 발표 3부의 확장판. 조건과 숫자는 전부 코드와 실측에서 가져왔다.

---

## 전체 그림

캡차를 푸는 30초 동안 우리는 **여섯 가지를 동시에** 봅니다.

```
① 궤적의 모양        어떻게 움직였나          ← AI 모델
② 멈춤과 재출발       멈췄다 어떻게 다시 갔나   ← 규칙
③ 서버 도착 시각      언제 도착했나            ← 규칙 · 위조 불가
④ 실행 환경          어떤 브라우저인가         ← 규칙
⑤ 행동 지문          전에 본 패턴인가          ← 해시 대조
⑥ 함정              건드리면 안 될 걸 건드렸나  ← 허니팟
```

**①만 AI이고 나머지는 규칙**입니다. AI 하나로는 못 막기 때문에 층을 쌓았습니다.

# ① 궤적의 모양 — AI가 보는 부분

## 무엇을 숫자로 바꾸나

마우스 궤적은 점의 나열입니다. 이걸 **50개 숫자**로 요약합니다.

**속도 계열**
```
avg_speed            평균 속도
max_speed            최고 속도
speed_std            속도의 흔들림
normalized_speed_p10/p50/p90   속도 분포의 10%·50%·90% 지점
```

**가속 계열**
```
avg_acceleration     평균 가속도
max_acceleration     최고 가속도
jerk_mean            저크 — 가속도가 변하는 속도
```
> **저크**가 왜 중요하냐면, 사람 손은 근육이라 가속도가 부드럽게 변합니다.
> 프로그램은 계산식대로 딱딱 바뀝니다.

**모양 계열**
```
linearity            얼마나 직선에 가까운가
y_deviation          직선에서 얼마나 벗어났나
turn_angle_mean/std  꺾이는 각도의 평균·흔들림
direction_changes    방향을 몇 번 바꿨나
```

**망설임 계열**
```
pause_count          멈춘 횟수
pause_ratio          전체 시간 중 멈춰 있던 비율
micro_move_ratio     아주 작은 움직임의 비율
dwell_burst_count    한곳에 머문 구간 수
overshoot_count      목표를 지나쳤다 되돌린 횟수
correction_count     막판에 위치를 고친 횟수
endpoint_adjustment_time   종점에서 미세조정한 시간
```

**시간 구조 계열**
```
interval_mean_ms     이벤트 간격 평균
interval_cv          간격의 불규칙성
interval_lag1_autocorrelation   직전 간격과 얼마나 닮았나
timing_entropy       시간 분포의 무질서도
spatial_entropy      공간 분포의 무질서도
```
> **자기상관**이 왜 중요하냐면, 사람은 간격이 들쭉날쭉하지만 **인접한 것끼리는
> 비슷합니다**(손이 갑자기 안 바뀌니까). 난수로 만들면 인접 간격이 서로 무관합니다.

## 실제로 갈리는 값

학습 데이터 사람 2만 · 봇 1만 3천에서 잰 값입니다.

| 특징 | 사람 | 봇 | 해석 |
|---|---:|---:|---|
| 방향 전환 있음 | **88%** (평균 4.9회) | 47% (2.0회) | 사람은 곧게 안 간다 |
| 멈춤 있음 | **98%** (평균 24.6회) | 59% (9.4회) | 사람은 자주 멈춘다 |
| 목표 초과 후 되돌림 | **47%** | 19% | 사람은 지나친다 |
| 종점 보정 있음 | **39%** | 23% | 사람은 막판에 고친다 |

**한 줄로: 사람은 망설이고, 지나치고, 되돌립니다.**

## 왜 두 개로 나눠 학습했나

50개를 두 갈래로 나눴습니다.

```
general    일반 궤적 47개   속도·방향·멈춤·엔트로피
dynamics   물리 41개        가속도·저크·회전각
```

각각 따로 학습시키고 **둘 중 낮은 점수**를 씁니다.

```
general 0.99 · dynamics 0.02  →  최종 0.02  (봇)
```

**봇이 두 관점을 동시에 속여야** 통과합니다. 한쪽만 흉내내면 다른 쪽에서 걸립니다.

# ② 멈춤과 재출발 — stop-go 패턴

## 무엇을 보나

사람이 마우스를 멈췄다가 다시 움직일 때는 **관성이 남습니다.** 스르륵 출발합니다.
프로그램은 딱 멈추고 딱 출발합니다.

이걸 두 조건으로 잡습니다.

```
조건 A · 멈췄다 급출발
  멈춘 뒤 재출발 거리 ≥ 0.20 (화면 비율)
  재출발에 걸린 시간 ≤ 350ms

조건 B · 종점 역방향 보정
  마지막 두 구간의 방향이 반대 (내적 < 0)
  보정 거리가 0.01~0.08 사이

둘 다 있으면 → step-up
```

## 왜 이 조합인가

**조건 A만으로는 부족합니다.** 사람도 급하게 움직일 때가 있습니다.

**조건 B가 결정적입니다.** 목표에 닿은 뒤 반대 방향으로 살짝 되돌리는 건 사람 특유의
동작인데, **이걸 흉내낸 봇은 A와 함께 나타납니다** — 사람다움을 계산으로 넣었기
때문입니다. 진짜 사람은 급출발과 종점 보정이 같이 나오는 일이 드뭅니다.

## 별도 신호 하나

```
sparse_pause_restart
  재출발이 있는데 이동 이벤트가 5개 이하
```

**움직임은 거의 없는데 멈췄다 다시 갔다**는 건 궤적을 성기게 만들었다는 뜻입니다.

# ③ 서버 도착 시각 — 위조가 불가능한 층

## 왜 이게 특별한가

앞의 ①②는 전부 **브라우저가 보낸 값**을 봅니다. 봇이 좋은 점수가 나오는 궤적을
계산해서 보내면 속습니다.

**서버가 언제 받았는지는 봇이 못 바꿉니다.**

## 어떻게 동작하나

캡차는 이벤트를 **200ms마다** 서버로 보냅니다. 다 모아서 한 번에 보내지 않습니다.

```
사람이 그리는 동안
  0.2초  →  배치 1 도착
  0.4초  →  배치 2 도착
  0.6초  →  배치 3 도착
  ...
```

봇이 궤적을 미리 만들어두고 한 번에 보내면 이렇게 됩니다.

```
브라우저 타임라인(자칭)   30초짜리 궤적
서버가 받은 시간          0.3초 만에 전부
```

**말이 안 됩니다.** 30초 동안 그렸다면서 0.3초 만에 도착할 수 없습니다.

## 판정 조건

```
클라이언트가 주장하는 궤적 길이 ≥ 1500ms
그런데 서버 수신 구간이 그보다 1200ms 이상 짧고
서버 수신 구간이 주장 길이의 45% 이하
  → step-up
```

**차단이 아니라 step-up 입니다.** 네트워크가 느리거나 끊겼다 이어질 수 있으니 여지를
남깁니다.

## 영수증 체인

배치마다 이전 배치의 해시를 담아 보냅니다.

```
배치1  →  hash1
배치2  →  이전=hash1 + 자기 내용  →  hash2
배치3  →  이전=hash2 + 자기 내용  →  hash3
```

중간을 빼거나 순서를 바꾸면 **사슬이 끊깁니다.** 그래서 유리한 구간만 골라 보낼 수
없습니다.

> **여기서 한 번 크게 당했습니다.** 저장할 때와 검증할 때 소수점 처리가 미묘하게
> 달라서 해시가 어긋났고, **배치가 통째로 버려지는데 캡차는 정상 통과**했습니다.
> 증상이 없어서 하루를 잃었습니다. 지금은 해싱 전에 반올림해서 맞춥니다.

# ④ 실행 환경 — 자동화 브라우저의 흔적

브라우저가 스스로 드러내는 값들입니다.

```
navigator.webdriver 가 true    +80점
헤드리스 브라우저 UA           +80점
언어 설정이 하나도 없음         +15점
CPU 코어 수가 0                +10점
```

**앞의 둘이 결정적입니다.** Selenium이나 Puppeteer를 그냥 켜면 `webdriver`가 true로
박힙니다.

숨길 수는 있습니다. 다만 **숨기는 것 자체가 비용**이고, 숨기지 않은 봇은 여기서 다
걸립니다. 공격 단가를 올리는 층입니다.

# ⑤ 행동 지문 — 같은 도구를 쓰는가

## 아이디어

같은 자동화 도구는 **같은 모양의 궤적을 반복 생성**합니다. 사람은 매번 다릅니다.

그래서 궤적의 특징을 **거칠게 버킷팅해서 해시**로 만듭니다.

```
반응시간 // 250ms
회전량 / 0.4 반올림
속도 변동계수 / 0.06 반올림
간격 변동계수 / 0.06 반올림
이동 수 (최대 25)
멈춤 수
총 이동거리 / 0.3 반올림
        ↓
      SHA-256 앞 16자리 = 행동 지문
```

**거칠게 자르는 게 핵심입니다.** 정밀하게 자르면 사람도 매번 다른 지문이 나오고,
너무 거칠면 사람끼리도 겹칩니다.

## 어떻게 쓰나

```
같은 지문이 여러 세션에서 나오면  →  공유 풀이툴로 판단해 차단
```

한 사람이 여러 번 푸는 건 정상이지만, **여러 세션이 같은 지문을 공유**하면 같은
프로그램이 돌고 있다는 뜻입니다.

# ⑥ 함정 — 허니팟

화면에 **건드리면 안 되는 객체**를 섞어 둡니다. 사람 눈에는 정답 후보로 안 보이는
자리에 있습니다.

```
JSON을 긁어서 전부 집는 봇   →  허니팟을 집는다  →  차단
이미지를 보고 고르는 봇      →  자연스럽게 피한다  ← 못 잡음
사람                       →  안 집는다
```

**한계가 분명합니다.** 시각 인식 봇은 허니팟을 안 집습니다. 이건 **API를 직접 긁는
봇**만 잡는 층입니다.

# 종합 — 점수를 어떻게 합치나

```
위험 점수 = 궤적 위험도 + 자동화 점수

  30 미만   normal
  30~60     suspicious
  60~80     high
  80 이상   automated

행동 점수 임계 이상  →  step-up (문제 한 번 더)
차단 점수 임계 이상  →  차단
지문 클러스터 감지   →  차단
```

거기에 **AI 모델 점수**가 별도로 들어갑니다. 지금은 `shadow` 라 기록만 하고 판정에는
반영하지 않습니다.

# 실제로 잡힌 사례

제가 브라우저 자동화로 캡차를 풀어봤습니다. **답은 맞혔습니다.**

```json
{"success": false, "step_up": true, "risk_level": "suspicious"}
```

정답인데 통과 못 했습니다. 제 드래그가 **직선으로 순간이동**하는 형태라 궤적 위험도가
올라갔습니다.

또 하나 — `teleport` 계열 봇은 이렇게 갈립니다.

```
드래그 하나당 중간 이동 이벤트

  teleport 봇    정확히 1개
  다른 봇        최소 2개 · 중앙 8개
  사람           최소 2.3개 · 중앙 11개
```

**중간 이동이 2개 미만이면 사람의 드래그가 아닙니다.** 이건 AI 없이 규칙으로 잡습니다.

# 각 층이 무엇을 막고 무엇을 못 막나

| 층 | 막는 것 | 못 막는 것 |
|---|---|---|
| ① 궤적 AI | 궤적을 대충 만든 봇 | 궤적을 잘 흉내낸 봇 |
| ② stop-go | 사람다움을 계산으로 넣은 봇 | 진짜 사람 |
| ③ 서버 도착 시각 | **미리 만들어 한 번에 보내는 봇** | 실시간으로 그리는 봇 |
| ④ 실행 환경 | 순정 자동화 도구 | 흔적을 지운 도구 |
| ⑤ 행동 지문 | 같은 도구를 여러 계정에 쓰는 것 | 매번 다르게 만드는 도구 |
| ⑥ 허니팟 | API를 긁는 봇 | 이미지를 보는 봇 |

**어느 하나도 단독으로는 못 막습니다.** 겹쳐서 공격 단가를 올리는 구조입니다.

그리고 **전부 못 막는 것이 하나 있습니다** — 진짜 사람이 대신 풀어주는 경우입니다.
행동으로 판별하는 층이라 원리적으로 불가능합니다.
