# 지영님께 — 마운트 지점 · env 값 회신 + 위젯 경로 실측 결과

조성원 · 2026-08-05

## 먼저 결론

물어보신 두 가지 답부터 드립니다.

```
① 마운트 지점        강의 시청 화면(GameScreen) 기준으로 붙여주세요
② MAIN_CAPTCHA_URL   https://www.catchap5.com/captcha-api  그대로 맞습니다
   SITE_SECRET       GPU 파일에 이미 있습니다 (아래 경로)
```

**다만 하나 더 있습니다.** 회신 주신 스니펫대로 붙이면 **위젯이 화면에 안 뜹니다.**
방금 프록시 경로를 실제로 호출해서 확인했고, 깨지는 지점이 세 군데입니다.
백엔드 verify 쪽은 문제 없고, **브라우저에 보이는 캡차 UI만** 안 뜹니다.

이건 민서 쪽 수정이 필요한 건이라 아래에 근거를 정리했습니다.

---

## ① 마운트 지점 — 시청 화면(GameScreen)

**시청 화면 기준으로 부탁드립니다.** 이유는 지영님이 짚으신 그대로입니다.

행동 모델은 **어느 화면에서 걷힌 데이터인지에 민감합니다.** 7월에 겪은 게 그거였습니다.

```
옛 수집 화면에서 잰 사람 오탐률      0.11%
메인 캡차 화면에서 잰 사람 오탐률   33.3%
```

같은 모델인데 화면이 달라서 300배 벌어졌습니다. 그래서 **차단을 할 화면과 데이터를
모을 화면이 같아야** 합니다. 차단 지점은 시청 화면이니 수집도 시청 화면이어야 합니다.

`/captcha` 데모 페이지는 **스니펫이 동작하는지 보는 스모크 테스트용**으로만 쓰고,
포인터 이벤트·스테이지 크기 확인은 시청 화면에서 하겠습니다.

## ② env 값

### MAIN_CAPTCHA_URL

```
MAIN_CAPTCHA_URL = https://www.catchap5.com/captcha-api
```

**맞습니다. 이 경로로 실제 왕복이 됩니다.** 방금 확인했습니다.

```bash
curl -s -w '\nHTTP %{http_code}\n' -X POST \
  https://www.catchap5.com/captcha-api/api/verify-token \
  -H 'Content-Type: application/json' \
  -d '{"token":"0000000000000000000000000000000000","session_id":"aaaaaaaaaaaa","purpose":"lecture"}'

{"detail":"Invalid site secret"}
HTTP 401
```

**401 이 나온다는 건 프록시가 요청을 캡차 앱까지 제대로 전달했다는 뜻입니다.**
(경로가 안 붙어 있으면 404 가 납니다.) 시크릿만 넣으면 200 이 나옵니다.

참고로 **백엔드→캡차는 서버 대 서버라 mixed content 와 무관**합니다. 프록시를 꼭
거칠 필요는 없지만, 프록시 경유가 더 낫다고 봅니다.

```
· 백엔드→프록시 구간이 TLS 로 덮인다 (캡차 IP 직접 호출은 평문)
· 캡차가 이사 가도 백엔드 env 를 안 건드려도 된다
```

### MAIN_CAPTCHA_SITE_SECRET

**채팅에 안 붙이신 판단이 맞습니다.** 값은 이미 서버에 놓여 있습니다.

```
GPU 서버 61.109.239.231
/tmp/catchap_site_secret.txt      ← 민서가 올려둔 것, 지영님 읽기 권한 있습니다
```

여기서 읽어서 백엔드 env 에 넣어주시면 됩니다. 제 쪽에서도 이 파일로만 다룹니다.

### site key 에 오타가 있습니다

회신에 적어주신 값과 실제 서버가 내려주는 값이 다릅니다.

```
회신 주신 값   site_wz4kko3e4rI8LFYf0KBsLpTmDQfP2a2
실제 값        site_wz4xkko3e4rI8LFYf0KBsLpTmDQfP2a2
                       ↑ x 한 글자
```

```bash
curl -s https://www.catchap5.com/captcha-api/api/config
{"siteKey":"site_wz4xkko3e4rI8LFYf0KBsLpTmDQfP2a2","embedOrigins":[]}
```

**이 값이 틀리면 챌린지 생성부터 실패합니다.** 다만 지금 위젯은 site key 를 프런트
data 속성으로 받지 않고 캡차 페이지가 `/api/config` 로 직접 가져갑니다. 그래서
**프런트에 안 박아도 됩니다.** 혹시 어딘가 하드코딩하셨으면 위 값으로 고쳐주세요.

## 토큰 수명 — 300초가 아니라 120초일 수 있습니다

회신에 300초로 적어주셨는데, 제가 8/04 에 실제로 토큰을 받아봤을 때는 120 이었습니다.

```
코드 기본값 (config.py)            VERIFICATION_TTL_SECONDS = 300
8/04 실제 응답                     {"success":true, "expires_in":120}
```

배포 env 가 300 을 120 으로 덮고 있는 것으로 보입니다. **민서에게 확인 요청하겠습니다.**
그전까지는 **짧은 쪽(120초) 기준으로 잡아주세요.** 300으로 잡아뒀다가 실제가 120이면
사용자가 만료로 튕기고, 반대는 아무 문제 없습니다.

## 그리고 — 지금 스니펫대로 붙이면 캡차가 안 뜹니다

`/captcha-api` 하위경로 프록시가 **서버 대 서버 호출(verify-token)에는 문제가 없는데,
브라우저에 캡차 UI 를 띄우는 경로는 세 군데가 깨집니다.** 전부 실제 호출로 확인했습니다.

### 깨지는 곳 1 — widget.js 가 하위경로를 버립니다

지금 배포된 `widget.js` 내용입니다.

```js
var origin = new URL(script.src).origin;   // ← origin 만 뽑습니다
...
iframe.src = origin + "/?" + params.toString();
```

`https://www.catchap5.com/captcha-api/widget.js` 로 불러도 `.origin` 은
`https://www.catchap5.com` 입니다. **`/captcha-api` 가 사라집니다.**

```
만들어지는 iframe src   https://www.catchap5.com/?embed=1&lecture=...
                        → 캡차가 아니라 플랫폼 홈페이지가 뜹니다
```

"하위경로 대응해 두셨다"고 전해 들으셨는데, **지금 배포본에는 반영이 안 돼 있습니다.**
(방금 프록시에서 받은 파일 기준입니다.)

### 깨지는 곳 2 — 캡차 페이지 asset 이 루트 절대경로입니다

```bash
curl -s "https://www.catchap5.com/captcha-api/?embed=1"

<script type="module" crossorigin src="/assets/index-BE7npigS.js"></script>
<link rel="stylesheet" crossorigin href="/assets/index-Exb-Gh5w.css">
```

`/assets/...` 로 절대경로라 브라우저가 `www.catchap5.com/assets/...` 를 찾아갑니다.

```
https://www.catchap5.com/assets/index-BE7npigS.js               HTTP 404
https://www.catchap5.com/captcha-api/assets/index-BE7npigS.js   HTTP 200 (212KB)
```

**파일은 하위경로에만 있고, HTML 은 루트에서 찾습니다.** 빈 화면이 됩니다.

### 깨지는 곳 3 — 캡차 JS 의 API 호출도 루트 절대경로입니다

번들 안을 보면 이렇습니다.

```js
await x(`/api/config`)
await x(`/api/captcha/challenges`, {method:`POST`, ...})
await x(`/api/captcha/challenges/${challenge_id}/...`)
```

`/api/...` 로 나가면 **플랫폼 백엔드로 갑니다.** 캡차 서버로 안 갑니다.

### 정리

```
                          하위경로 프록시에서
백엔드 → verify-token         ✅  동작 확인 (401 반환)
브라우저 → 캡차 UI            ❌  세 군데 전부 루트 절대경로
```

**verify 쪽은 지영님 말씀대로 손댈 게 없습니다.** UI 만 막혀 있습니다.

## 제안 — 캡차에 전용 호스트를 루트로 주는 게 제일 짧습니다

```
https://captcha.catchap5.com/   →   http://61.109.239.231:8000/   (루트 그대로)
```

이러면 위 세 개가 **한 번에** 풀립니다. 캡차 프런트를 다시 빌드할 필요가 없습니다.

```
widget.js 의 .origin      https://captcha.catchap5.com   ✅
/assets/...               루트라서 그대로 맞음            ✅
/api/...                  루트라서 그대로 맞음            ✅
```

**대신 민서 쪽에 env 하나가 필요합니다.**

지금 캡차가 내려주는 헤더가 이렇습니다.

```bash
curl -sD - -o /dev/null https://www.catchap5.com/captcha-api/api/config | grep -i content-security
content-security-policy: frame-ancestors 'self'
```

`embedOrigins` 가 비어 있어서 **자기 자신 외에는 iframe 이 금지**됩니다. 지금
하위경로 프록시에서는 캡차와 플랫폼이 같은 오리진이라 이게 안 걸렸는데,
**전용 호스트로 분리하면 오리진이 달라져서 iframe 이 막힙니다.**

```
민서 쪽 설정 필요
EMBED_ORIGINS=https://www.catchap5.com

→ frame-ancestors 'self' https://www.catchap5.com  으로 바뀌고 임베드 허용
```

**대안**(전용 호스트가 어려운 경우)은 민서가 캡차 프런트를 상대경로로 재빌드하고
widget.js 도 고치는 건데, **빌드 설정·API 베이스·위젯 세 군데를 다 고쳐야 해서**
훨씬 깁니다. 전용 호스트 쪽을 권합니다.

**이건 제가 민서에게 따로 요청하겠습니다.** 지영님은 결정만 알려주시면 됩니다
(전용 호스트로 갈지 / 하위경로 유지하고 캡차를 재빌드할지).

## 스테이지 크기 — 제약은 안 겁니다. 대신 기록만 남겨주세요

크기 제약을 걸지 않겠다는 데 동의합니다. 다만 **정규화는 아직 배포 전**이라
현재 모델은 특징 50개 중 17개가 픽셀 단위입니다.

그래서 부탁은 하나입니다.

```
캡차 스테이지의 실제 픽셀 폭·높이가 이벤트와 함께 기록되게만 해주세요
```

지금 규약에 이미 들어 있는 값이라 새로 하실 건 없고, **iframe 안에서도 그 값이
제대로 실려 나오는지**만 붙인 뒤 같이 확인하면 됩니다. 이 값이 있으면 나중에 정규화로
크기 차이를 없앨 수 있고, 없으면 되돌릴 수 없습니다.

## 지영님이 하실 일 정리

```
지금 바로 가능
  · MAIN_CAPTCHA_URL = https://www.catchap5.com/captcha-api      설정
  · MAIN_CAPTCHA_SITE_SECRET  ← GPU:/tmp/catchap_site_secret.txt  설정
  · site key 하드코딩한 곳 있으면 오타 수정 (wz4x…)
  · 토큰 만료 처리는 120초 기준으로

민서 수정 이후
  · 시청 화면(GameScreen)에 위젯 스니펫 삽입
  · 붙으면 알려주시면 제가 포인터 이벤트·스테이지 크기 확인하겠습니다
```

**검증(백엔드)은 준비되셨다는 것 확인했습니다.** 남은 건 위젯이 실제로 뜨게 하는
것뿐이고, 그건 민서 쪽 건이라 제가 넘기겠습니다.

## 부록 — 민서에게 보낼 내용 (지영님 참고용)

```
1. widget.js 가 new URL(script.src).origin 을 써서 하위경로를 버립니다.
   /captcha-api/widget.js 로 부르면 iframe src 가 플랫폼 홈으로 갑니다.

2. index.html 의 /assets/... 와 번들 안의 /api/... 가 루트 절대경로라
   하위경로 프록시에서 404 / 오배송됩니다.

3. 제안: captcha.catchap5.com 을 루트로 붙이면 셋 다 해결됩니다.
   대신 EMBED_ORIGINS=https://www.catchap5.com 설정이 필요합니다
   (지금 frame-ancestors 'self' 라 다른 오리진에서 iframe 이 막힙니다).

4. VERIFICATION_TTL_SECONDS 가 코드 기본값 300 인데 실측은 120 입니다.
   배포 env 실제 값이 무엇인지 알려주세요.
```
