## 1. 어떻게 공격했나 / 무엇이 뚫렸나

| 공격 | 방법 | 결과 |
|---|---|---|
| weakset retime | 저장된 우회후보 89건의 **시각만** 현재 창으로 이동(좌표 불변) | **40.4% 통과** |
| **실제 사람 재생** | 진짜 사람 궤적 120건을 시각만 옮겨 제출 | **97.5% 통과** 🔴 |
| **변종 공장** | 통과후보 1건에 좌표지터·스케일·이동·시간변형 | **92.2% 통과** 🔴 |
| 합성 봇 16종×3 | 직선/곡선/베지어/stop-go/오버슛/사람흉내 등 | 0% (전부 차단) |
| 블랙박스 검색 | 직선봇에서 점수 보고 400회 변이 | 실패(점수 포화) |
| 시간창 변형 B1~B7 | 시각 이동·압축·확장·창밖·필드누락 | 창 안이면 전부 통과 |

핵심: 손제작 봇은 모델이 100% 차단한다. 그러나 **사람처럼 보이도록 미리 만든
궤적**(사람 녹화본이든 생성기 evader든)은 시각만 맞추면 통과한다. 가장 치명적인
것은 사람 재생 97.5% — 사람 세션을 한 번 녹화하면 무한 재사용 가능하며, 모델이
아무리 정확해져도 진짜 사람 궤적이라 원리상 막을 수 없다.

## 2. 왜 뚫렸나 (근본 원인)

> 실패 지점은 **모델 정확도가 아니라 "입력 신뢰"다.** 서버가 브라우저가 제출한
> 이벤트를 사실상 그대로 믿기 때문에, 미리 계산한 궤적을 검증 순간에 통째로
> 바꿔 끼울 수 있다.

모델·임계값·정책모드 어떤 조정으로도 재생 공격은 닫히지 않는다(통과분이 `allow`라
`active` 승격도 무효).

## 3. 어떻게 보완했나

### A. 실제 배포 코드에 반영

**① 하드닝 (커밋 `74ec5e7`)**
- 온라인 `/predict` 서버 시간창 검증 + 품질거부 시 고득점이어도 step_up 상한.
- 합성 봇·상대시각 재생·순진한 위조 차단.
- 한계 명시: "부분 방어이며 출처 증명 아님."

**② 세션속도 버그 수정 (커밋 `103afe2`) — 이번에 발견한 실제 결함**
- 발견: `session_rate_exceeded`가 분당 20회에서 발동해도 action이 `allow`였다.
  `session_rate_weight(30) < medium(40)`이라 속도 신호 단독으론 step_up에 못
  미쳐, 분당 30회 재생 폭주도 전부 통과(reason만 로그).
- 수정: 속도 초과 시 risk를 medium으로 floor → 20+/min은 step_up. 사람은 분당
  20회 CAPTCHA를 풀지 않으므로 FRR 안전. 회귀 테스트 추가, 전체 201 passed.

**③ 이벤트 수 상한 (커밋 `0d8e9fa`) — 이번에 발견한 자원 결함 (R10)**
- 발견: `/predict`·`/collect`에 이벤트 수/페이로드 상한이 없어 10만개(18.7MB,
  1.7초 CPU)가 그대로 수락됨 — 경미한 DoS 표면.
- 수정: 스키마에 `MAX_EVENTS_PER_ATTEMPT=5000`(사람 최대 ~1500의 3배 이상).
  정상 드래그는 절대 거부 안 되고 초과분은 채점 전 422. 회귀 테스트 추가.

**참고 — 확인만 되고 수정 불필요(안전)**
- 입력 강건성(R10): malformed(NaN·극단·역행·타입오염) 전부 step_up|422,
  fail-open/크래시 없음.
- 클라이언트 자기신고 필드(R11): interaction 카운터는 배포 two-view 모델의
  50개 feature에 미포함 → 조작해도 점수 불변. (가드레일: 향후 모델 승격 때
  클라 조작 가능 필드를 feature로 넣지 말 것.)
- 미사용 replay 신호(R8/R9): endpoint는 사람 88.7% 공유, duration은 ±5ms로
  무력화 → 미사용이 정당.

배포본 갱신: 위 하드닝 3파일(quality_validator/risk_fusion/predict)이 GPU
서버 배포본(`/home/sw/catchap-behavior`)에도 반영 완료(백업 후 scp+재시작,
상대시각 거부로 동작 확인). 세션속도·이벤트상한 수정은 로컬 커밋 반영, 배포
반영은 다음 갱신 시 포함.

### B. 프로토타입 검증 (온라인 경로 미연결 — 배치 전송 계층 대기)

**③ 전송 타이밍 결속 (`tools/delivery_binding.py`)**
- 서버 기록 배치 도착시각 vs 클라이언트 타임라인 상관 검사.
- 미리 만든 궤적을 검증 직전 일괄/빠르게 던지면 탐지 → 버스트 재생 100% 차단,
  FRR 1.7%.

**④ nonce + receipt chain (`tools/receipt_chain.py`)**
- 일회성 nonce + HMAC receipt 체인 + sequence.
- receipt 위조·재사용·sequence 조작·verify 재생 100% 차단, FRR 2.5%.

**⑤ 통합 정책 스케치 (`tools/online_policy_sketch.py`)**
- 게이트가 모델보다 먼저 실행, 게이트는 하향만 가능(통과가 곧 allow 아님).

## 4. 방어 계층 종합 (막는 것 / 사각지대)

| 계층 | 막는 것 | 사각지대 |
|---|---|---|
| 모델 two-view | 손제작 봇 (0%) | 사람형 궤적 |
| 시간창 검증 | 창 밖 시각 | 창 안 재생(대기만) |
| 전송 결속 ③ | 버스트/빠른전송 100% | 페이싱 재생 ±400ms |
| receipt chain ④ | 위조·재사용·seq gap | 유효체인 재생 |
| 재생탐지 DTW | literal·translate·scale | 좌표지터·녹화로테이션 |
| 세션속도 ② | 분당 20회+ 반복 | 저속 공격 |
| 특징 gate | (안전한 단일 gate 없음) | — |

**모든 계층을 통과하는 유일한 공격** = 페이싱 전송(±400ms) + 좌표지터변종 또는
개별 녹화 로테이션, 저속(<20/min). 이것이 클라이언트 제출형 프로토콜의 최종
잔존 위협이며 서버 주입 실시간 신호로만 닫힌다.

## 5. 근본 한계 (정량화만, 억지수정 안 함)

반응적 규칙으로 막으면 FRR만 악화(실제로 min-gap 규칙이 FRR 35% 유발 후 제거,
iter1 교훈).

1. **페이싱 실시간 재생**: 배치 타이밍을 녹화 대비 ±400ms 안에 재현하면 통과
   (저비용). 정상 사용자도 같은 지터라 못 조임.
2. **짧은 녹화(<800ms) 버스트**: 사람의 14.2%가 그만큼 짧고, 짧으면 전송검사
   면제라 통과.
3. **모델 특징 계층**: FRR<3%에서 evader 분리하는 안전한 단일 특징 없음
   (최선 vel_cv 63.9%도 생성기 특성이라 사람 재생은 통과, weakset 과적합).
4. **미사용 신호(`repeated_endpoint`/`repeated_duration`)**: endpoint는 사람
   88.7%가 끝점 공유(FRR 위험), duration은 ±5ms 지터로 무력화(두더지잡기).
   둘 다 미사용이 옳음.

완전 차단은 클라이언트가 오프라인 재현 불가한 신호(수집 중 서버 주입 실시간
challenge, attestation)를 요구하며, 계약서 §8도 완전 증명은 클라이언트 측만으론
불가능하다고 명시. 운영 대응: 세션 위험 누적·시도 제한·요청 빈도 제한으로 반복
악용 비용을 높인다(②가 그 첫 조치).

## 7. 배포·연동 상태와 다음 순서

정찰 결과: 행동 AI는 이미 GPU 서버 `/home/sw/catchap-behavior`에서 가동 중이나
**하드닝 미반영**(커밋 `74ec5e7`는 로컬만), 캡차가 호출 안 함(`POST /predict`
0건), MySQL 미설정, systemd 없음, git 아님.

연동 순서:
1. 배포본을 하드닝+세션속도수정 버전으로 갱신
2. `.env` MySQL 설정 → shadow 기록 + **재생탐지 DTW 계층 즉시 활성화(무비용)**
3. shadow 연동(`BEHAVIOR_EVENT_TRANSPORT=shadow`) → Human FRR 최초 실측
4. 배치 수집 전송 계층 구현 → delivery/receipt 프로토타입을 온라인 경로에 연결
5. 그 후에만 `active` 검토. **단 `active`도 재생 우회는 못 막음**(통과분이
   allow). 프로토콜 전송 계층이 선행이며, Human FRR 실측이 모든 정책 승격의
   선행 조건.
