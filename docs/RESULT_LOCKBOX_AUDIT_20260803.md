# 봉인 홀드아웃 대장 점검 — 라벨을 믿을 수 없다

조성원 · 2026-08-03

---

## 결론

밀봉 홀드아웃 대장을 처음으로 기계 검증했다. **문제 4건이 나왔다.**

| | |
|---|---|
| 매니페스트 JSON 파손 | 1건 — 스캔에서 조용히 빠진다 |
| 홀드아웃인데 학습 데이터와 100% 겹침 | 3건 · 22,000행 |
| 봉인 해시로 무결성 검증 가능한 것 | **11건 중 0건** |
| 실제로 쓸 수 있는 봇 홀드아웃 | 8건 |
| 사람 홀드아웃 | **0건** |

승급을 하려면 밀봉 채점이 필요한데, **채점할 대상 목록 자체가 틀려 있었다.**

---

## ① 홀드아웃이라고 표시된 것이 학습 데이터였다

`training_usage: external_holdout_only` 로 적혀 있는데 학습 세트와 행 단위로
100% 겹치는 것이 셋이다.

```
extended_bots_10000_20260715                 10,000행  100% 겹침
extended_bots_10000_20260721                 10,000행  100% 겹침
adversarial_replay_development_2000_20260721  2,000행  100% 겹침
```

학습 봇 특징이 13,300행인데 그중 12,000행이 "홀드아웃" 으로도 표시돼 있다.

**이걸로 채점하면 학습 데이터로 채점하는 것이다.** 숫자는 훌륭하게 나오고 아무
의미가 없다. 다음 주에 대장을 보고 "미소진 홀드아웃이 11개 남았다" 고 판단했으면
그중 셋을 그렇게 썼을 것이다.

`adversarial_replay_development_2000` 은 이름에 `development` 가 들어 있는데도
`external_holdout_only` 로 표시돼 있다. **이름과 메타데이터가 서로 다른 말을 한다.**

---

## ② 매니페스트 하나가 깨져 있다

```
data/interim/revalidation_bot_lockbox_b13300_v23corr_20260722/
  bot_lockbox.jsonl.manifest.json
    → JSON 파손: Extra data: line 11 column 1
```

닫는 중괄호가 하나 더 있다. 내용을 직접 읽어 보면 이미 `baseline` 후보에 소진된
락박스인데, **파싱에 실패하는 파일을 건너뛰는 스캔은 이걸 "미소진" 으로 보고한다.**

읽을 수 없는 파일을 표에서 빈칸으로 처리하면 안 되는 이유가 이것이다. 그래서
검증기는 못 읽는 것을 전부 오류로 올린다.

---

## ③ 봉인 무결성을 증명할 수 있는 것이 하나도 없다

봉인의 핵심은 "그때 봉인한 것과 지금 파일이 같다" 를 증명하는 것이다. 그 증명은
디렉터리 매니페스트의 `files[].sha256` 으로만 가능한데, 그 구조를 가진 것은
`revalidation_*_lockbox` 둘뿐이고 **둘 다 이미 소진됐다.**

남아 있는 홀드아웃 11건은 sha256 기록이 없다. 파일이 그 사이에 바뀌었는지,
다시 생성됐는지 알 방법이 없다.

**지금 "봉인" 은 파일 이름과 관행이지 검증 가능한 상태가 아니다.**

## 소진 규칙 — 앞으로 이렇게 한다

지난번에 락박스가 소진된 것은 규칙이 없었기 때문이다.

1. **홀드아웃은 최종 후보에만 쓴다.** 재학습 계획이 있으면 채점하지 않는다.
   지금 드래그 단위 스코어링과 재학습이 예정돼 있으므로, **이번 주에는 어떤
   홀드아웃도 열지 않는다.**
2. **한 후보에 한 번.** 같은 홀드아웃으로 두 번 채점하지 않는다. 두 번째부터는
   그 데이터에 맞추는 것이 된다.
3. **채점하면 즉시 `evaluation_consumed` 를 기록한다.** 모델 경로·보고서 경로·시각.
4. **여는 사람이 대장을 먼저 돌린다.** `tools/lockbox_audit.py --strict` 가
   0을 반환하지 않으면 열지 않는다.
5. **`training_usage` 라벨을 믿지 않는다.** 학습 세트와의 행 겹침으로 판단한다.
   검증기가 자동으로 확인한다.

## 새 사람 홀드아웃 설계 — 수집 전에 정한다

수집 후에 정하면 데이터를 보고 나누는 것이 된다.

**참여자 단위로 자른다.** 같은 사람의 세션이 학습과 평가에 동시에 들어가면
FRR이 낙관적으로 나온다. 현 모델도 참여자 그룹으로 잘라 보정했다.

**최소 8명이 필요하다.** 5명이면 학습 3 / 홀드아웃 2 인데, 참여자 3명으로는
참여자 그룹 기반 임계값 보정이 성립하지 않는다(현 모델은 사람 29그룹).

```
8명 이상   학습 5~6명 / 홀드아웃 2~3명    → 이번 주 승급 가능
5명        전원 학습, 홀드아웃은 다음 창   → 승급은 다음 주
```

**봉인 시점은 수집 직후, 점수를 보기 전이다.** 봉인할 때 기록할 것:

```
파일 sha256 · 행 수 · 참여자 ID 목록 · 봉인 시각 · 봉인한 사람
```

**장치를 홀드아웃에도 넣는다.** 마우스만 학습하고 트랙패드를 홀드아웃에 몰면
"처음 보는 장치" 를 재는 것이지 "처음 보는 사람" 을 재는 것이 아니다. 양쪽에
마우스·트랙패드·터치가 모두 들어가게 나눈다.

## 도구

```bash
.venv/bin/python tools/lockbox_audit.py            # 보고
.venv/bin/python tools/lockbox_audit.py --strict   # 문제가 있으면 비정상 종료
```

읽을 수 없는 파일, 해시 불일치, 학습 데이터와의 겹침을 전부 오류로 올린다.
표의 빈칸으로 넘기지 않는다.
