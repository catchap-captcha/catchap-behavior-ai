# 시험 트래픽을 통계에서 빼는 법 (2026-08-13)

## 왜 필요한가

시험용 봇이 운영을 두드리면 그 기록이 **실사용자와 같은 자리에 같은 모양으로** 남는다.
사용자가 적을 때는 몇 판이 통계를 통째로 흔든다.

0813 실측이 그 예다. 로그인 캡차 채점 99건에 거절률 27.3% 로 찍혔는데, **99건이 전부
우리 봇**이었다. 그 봇은 거절당하라고 만든 것이라 저 27.3% 는 아무 의미가 없다.
그런데 표에는 의미 있어 보이게 앉아 있다.

앞으로 재야 할 숫자 둘이 이것 없이는 못 잰다.

- **오탐율** — 승격 판단의 기준
- **같은 문항 재시도 비율** — 재생 바닥값(catchap-behavior-ai#26)의 근거가 이 숫자 하나다

## 지금부터: 세션 번호로 구분된다

시연·시험 도구가 세션 번호를 `guard-test-` 로 시작하게 만든다. 실제 사이트는 이 모양을
절대 만들지 않는다(위젯은 `guard-<시각>-<무작위8자>` 를 만든다).

- `tools/demo_block_direct.mjs` — 자기 번호를 직접 만든다
- `tools/demo_video_bot.mjs` — 화면이 뜨기 **전에** `sessionStorage` 에 심는다.
  위젯은 첫 렌더에서 읽고 없으면 새로 만들기 때문에 순서가 중요하다.

측정할 때는 이 한 줄을 더한다.

```sql
AND c.session_id NOT LIKE 'guard-test-%'
```

## 0813 이전 기록: 목록으로 빼야 한다

그날 브라우저 봇은 위젯이 만든 번호를 그대로 썼다. **글자 모양이 실사용자와 똑같아
패턴으로는 못 거른다.** 그날 로그인 세션 28개는 확인 결과 **전부 우리 봇**이고
실사용자는 한 명도 없었다. 그래서 날짜로 통째로 빼면 된다.

```sql
-- 0813 로그인 트래픽은 전부 시험용이다. 그날은 통째로 뺀다.
AND NOT (DATE(a.created_at) = '2026-08-13' AND c.purpose = 'login')
```

## 한계

이건 규칙이지 강제가 아니다. **새 시험 도구를 만들 때 접두어를 안 붙이면 같은 일이 또
난다.** 그래서 도구 안에 박아 뒀지 사람이 매번 붙이게 두지 않았다.

서버는 안 고쳤다. 세션 번호는 서버가 받아 적기만 하는 값이라 모양만 맞추면 된다.
