# 모델을 어떻게 고르나 — 선정 규칙

조성원 · 2026-08-05

---

## 왜 규칙이 필요한가

모델을 여러 개 만들면 그중 하나를 골라야 합니다. 그런데 **점수를 보고 고르면**
문제가 생깁니다.

```
후보 5개를 만들고 점수를 본다
  → 제일 좋은 걸 고른다
  → 그 점수를 "우리 모델 성능"이라고 발표한다
```

이게 왜 문제냐면, **5개 중 제일 좋은 것**은 운이 좋았을 수도 있기 때문입니다.
동전 5개를 던져 앞면 나온 걸 고르고 "이 동전은 앞면이 잘 나온다"고 하는 것과 같습니다.

그래서 **고르는 규칙을 미리 정하고, 결과를 보고 바꾸지 않습니다.**

---

## 1. 여러 후보 중 하나 고르기

`training/select_best_model.py` 에 순서대로 박혀 있습니다.

```
1  사람 오탐률 3% 이하인 것만 후보로 남긴다
2  그중 봇을 제일 많이 잡는 것
3  동점이면 사람 판별 F1 점수가 높은 것
4  또 동점이면 추론이 빠른 것
5  아무도 3%를 못 넘기면 아무것도 안 고른다
```

**5번이 중요합니다.** "그래도 제일 나은 걸 쓰자"가 아니라 **아무것도 안 고르고
프로덕션을 그대로 둡니다.** 기준 미달이면 교체하지 않습니다.

---

## 2. 네 단계 관문

고른 모델을 바로 쓰지 않습니다. 네 단계를 거칩니다.

```
실험 후보  →  Observation  →  Shadow  →  Production
   보관        기록만        판정하되      실제 차단
                            적용 안 함
```

### ① 실험 후보 — 파일로 보관할 자격

| 항목 | 기준 |
|---|---|
| 사람 오탐률 | 일반 test와 **모든** 봇 계열 홀드아웃에서 3% 이하 |
| 알려진 봇 통과율 | 5% 이하 |
| **처음 보는 봇 계열 최악 통과율** | **10% 이하** |
| 재생 공격 통과율 | 5% 이하 |

**"모든 계열에서"** 가 핵심입니다. 평균이 아니라 **최악값**을 봅니다. 한 계열만
크게 뚫려도 탈락입니다.

### ② Observation — 차단 없이 기록

```
사람 오탐률 3% 이하
실제 차단은 하지 않음
```

### ③ Shadow — 판정은 하되 적용 안 함

```
실험 후보 기준 전부 통과
+ 새 외부 홀드아웃이 반드시 존재
+ 그 홀드아웃에서 봇 통과율 5% 이하
```

**지금 우리 모델이 여기 있습니다.** 점수를 매기고 기록하지만 사용자에게는 아무 영향이
없습니다.

### ④ Production — 실제 차단

```
Shadow 조건 전부
+ 사람 오탐률 1% 이하   ← 더 엄격해집니다
```

차단을 하는 순간 오탐이 곧 서비스 중단이라 기준이 3배 엄격해집니다.

---

## 3. 홀드아웃 규칙 — 한 번만

**모델을 만드는 동안 절대 안 열어보는 데이터**입니다. 다 만든 뒤 딱 한 번 채점합니다.

### 왜 한 번인가

열어서 점수를 보면 **그 결과를 보고 모델을 고치게** 됩니다. 그러면 그 데이터도
공부한 데이터가 됩니다.

```
1회차   봉인 열고 채점 → 9.06% → "고쳐야겠다"
2회차   고친 모델로 같은 데이터 채점 → 좋게 나옴
        그런데 그건 그 데이터에 맞춘 것뿐
```

### 실제로 이걸로 후보 하나가 탈락했다

```
7/22 후보 모델

  공부한 데이터로 잰 오탐률    2.39%   "괜찮네"
  봉인 데이터로 잰 오탐률      9.06%   탈락
```

**4배 차이.** 봉인 데이터가 없었으면 올렸을 겁니다.

### 규칙을 문서로 못박았다

8/03에 대장 검증기를 만들면서 규칙도 같이 정했습니다.

```
1  홀드아웃은 최종 후보에만 쓴다. 재학습 계획이 있으면 열지 않는다
2  한 후보에 한 번. 두 번째부터는 그 데이터에 맞추는 것이 된다
3  채점하면 즉시 소진 기록을 남긴다 (모델·보고서·시각)
4  여는 사람이 대장 검증을 먼저 돌린다. 문제가 있으면 열지 않는다
5  "홀드아웃"이라는 라벨을 믿지 않는다. 학습 데이터와 겹치는지 직접 대조한다
```

**5번은 실제 사고에서 나왔습니다.** 홀드아웃으로 표시된 데이터 3개가 알고 보니
학습 데이터와 100% 겹쳤습니다. 그대로 채점했으면 학습 데이터로 시험 본 셈입니다.

## 4. 메인 캡차 기준 — 결과를 보기 전에 정했다

위 기준은 옛 수집 화면에서 만든 것입니다. 실제 서비스 화면에서 쓸 기준을
**7월 30일에 따로 정했습니다.**

```
전체 사람 오탐률 ≤ 2%
최악 참여자 오탐률 ≤ 5%
검증 참여자 5명 전원
조건 그룹 12개 이상
```

**중요한 건 날짜입니다.** 결과를 보기 전에 정했습니다.

그리고 다음 날 실측이 **33.3%** 로 나왔습니다. 기준의 16배입니다.

**고치지 않았습니다.** 숫자를 보고 기준을 고치면 그 기준이 의미를 잃기 때문입니다.

---

## 5. 왜 참여자 단위로 나누나

오탐률을 잴 때 **같은 사람이 학습과 평가 양쪽에 들어가면 안 됩니다.**

```
잘못된 방법   세션을 섞어서 80%는 학습, 20%는 평가
              → 같은 사람이 양쪽에 들어감
              → "이 사람은 이렇게 움직인다"를 외운 것
              → 처음 보는 사람에게는 안 통함

올바른 방법   사람 단위로 자른다
              A·B·C 로 학습, D·E 로 평가
```

**실제로 이걸로 한 번 속았습니다.** 8/03에 참여자 코드로 잘랐는데, `sw-mouse` 와
`sw-mouse-v2` 가 같은 사람의 다른 날이었습니다. 같은 사람이 양쪽에 들어가서
숫자가 좋게 나왔고, 사람 단위로 고치니 나빠졌습니다.

## 6. 지금 어디에 있나

| 관문 | 기준 | 현재 |
|---|---|---|
| 실험 후보 · 사람 오탐 | ≤3% | 0.7~2.2% ✅ |
| 실험 후보 · 알려진 봇 | ≤5% | 3.6% ✅ |
| 실험 후보 · **처음 보는 봇 최악** | **≤10%** | **3.3%** ✅ |
| Shadow · 새 외부 홀드아웃 | 필요 | **소진** ❌ |
| Production · 사람 오탐 | ≤1% | 미확정 |
| 메인 캡차 · 참여자 | 5명 | **2명** ❌ |

**성능 기준은 통과합니다. 검증 자료가 없어서 못 올립니다.**

## 7. 발표에서 이렇게 말하면 됩니다

> 모델을 고르는 규칙을 **결과를 보기 전에** 정해뒀습니다. 사람 오탐률 3% 이하인
> 것만 후보로 삼고, 그중 봇을 제일 많이 잡는 것을 고릅니다. **아무도 기준을 못
> 넘기면 아무것도 안 고르고 기존 모델을 그대로 둡니다.**
>
> 그리고 최종 검증용 데이터는 봉인해두고 **딱 한 번만** 채점합니다. 실제로 7월에
> 후보 하나가 이 검증에서 2.39%가 9.06%로 튀어 탈락했습니다.
>
> 지금 성능 기준은 통과합니다. 다만 **검증용 데이터를 다 써버려서** 새로 모으기
> 전까지는 승급 판정을 할 수 없습니다.
