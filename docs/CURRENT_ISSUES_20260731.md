## A. 보안 — 지금 바로 조치가 필요한 것

### A-1. 캡차 `:8000`이 인터넷에 전면 공개됐다 · **실측**

```
http://61.109.239.231:8000/api/config              200
http://61.109.239.231:8000/health/ready            200
http://61.109.239.231:8000/admin                   200   ← 라벨링 콘솔
http://61.109.239.231:8000/api/admin/queue         401   (키로 막힘)
```

관리 API 는 키로 막혀 있어 즉시 털리는 상태는 아니다. 다만 **관리 콘솔 페이지와
전체 API 표면이 인터넷에 노출**돼 있고, 남은 방어는 관리자 키 하나뿐이다.
팀 미완 목록의 "시크릿·관리자키 로테이션"이 아직인 상태에서 열렸다.

### A-2. `ALLOWED_ORIGINS`가 실제로 강제되지 않는다 · **실측**

```
Origin: https://evil.example  로 챌린지 요청  →  201 Created
```

`check_origin()` 은 구현돼 있지만 `allowed_origins` 가 `*` 이거나 비어 있으면
그냥 통과한다(`app/main.py`). 배포본이 그 상태다. **아무 사이트나 이 캡차를
호출할 수 있다.**

### A-3. 프레이밍 차단 헤더가 없다 · **실측**

```
X-Frame-Options            없음
Content-Security-Policy    없음  (frame-ancestors 없음)
```

즉 **아무 사이트나 이 캡차를 iframe 으로 끼울 수 있다.**

### A-4. A-2 · A-3 · postMessage 가 이어지면 토큰이 새어나간다 · **코드 + 실측**

`src/main.jsx:271`

```javascript
window.parent.postMessage({ type: "catchap-verified", token: ..., lecture_id: ... }, "*")
```

`"*"` 는 **어느 부모창이든 이 토큰을 받는다**는 뜻이다. 여기에 A-2(아무 Origin
허용) + A-3(아무 데서나 iframe 가능)이 겹치면 이렇게 된다.

```
악성 페이지가 캡차를 iframe 으로 끼움
  → 방문자가 캡차를 풂 (사람이 직접 푼다)
  → postMessage 가 "*" 라 악성 페이지가 토큰을 받음
```

**완화 요소는 있다.** 토큰은 `lecture_id`·`session_id` 에 묶이고, 서버검증에
사이트 시크릿이 필요하고, 1회용이다. 그래서 즉시 계정 탈취로 이어지지는 않는다.
다만 "사람에게 캡차를 대신 풀리는" 경로가 열려 있는 것은 사실이고, 이건 저희가
막으려던 위협 그 자체다.

> 이 셋(A-2·A-3·A-4)은 개별로는 낮은 위험으로 평가했던 것들이다.
> **공개 개방과 동시에 서로 연결됐다.** 셋 중 하나만 막아도 사슬이 끊긴다.

### A-5. HTTPS 가 아니다 · **실측**

`https://61.109.239.231:8000` 은 연결되지 않는다. 평문 HTTP 로 공개돼 있어
사이트 키·토큰이 중간에 노출된다.

## B. 모델 — 승격을 막는 것

### B-1. 승격된 모델이 없다 · **실측**

`models/production/` 은 `.gitkeep` 하나뿐. 지금 서빙되는 것은
`models/candidate/revalidation_two_view_participant_safe_20260722` 이고
`policy_mode=shadow` 라 판정에 반영되지 않는다.

### B-2. 후보가 밀봉 홀드아웃 채점을 한 번도 못 받았다 · **실측**

```
human_lockbox.jsonl.manifest.json
  evaluation_consumed = { model_path: .../revalidation_two_view_baseline_20260722,
                          scored_at_utc: 2026-07-22 }
```

지금 후보(`participant_safe`)가 아니라 **이전 후보(`baseline`)를 채점하는 데
써버렸다.** 남은 숫자는 전부 개발 데이터의 OOF 이고, threshold 도 그 OOF 로
골랐다. 편향 없는 성능 추정치가 없다.

미소진 봇 홀드아웃은 남아 있다(`vae_bots_external_holdout_1000`,
`ml_pca_gmm_external_holdout_1000`, `adversarial_replay_holdout_1000`,
`replay_warp_external_1000`). **사람 쪽만 없다.**

### B-3. 메인 캡차에서 나온 사람 데이터가 0건이다 · **실측**

```
catchap_ai.ai_behavior_attempts  라벨별: {'bot': 18}
```

사람 0건. 기존 20,066건은 **이전 수집 도구** 분포다. 지금 서비스하는 캡차의
사람 궤적은 한 건도 없다.

### B-4. 사람 속도로 움직이는 봇이 통과한다 · **실측 (표본 작음)**

같은 직선 궤적인데 전달 방식만 다르다.

| 그룹 | 건수 | 평균 human_prob | allow |
|---|---:|---:|---:|
| `botprobe linear/real` (실제 sleep, 사람 속도) | 5 | **0.999986** | **1** |
| `botprobe linear/synthetic` (산술 시각) | 7 | 0.988212 | 0 |
| `rtbot straight_uniform` (0.8초 완주) | 1 | 0.000000 | 0 |

**표본이 5·7·1건이다. 방향은 뚜렷하지만 단정할 수 없다.** 각 50건은 필요하다.

원인 추정: 학습·시험에 쓴 봇이 전부 산술 타임스탬프에 1초 미만 완주라,
모델이 "빠르고 규칙적 = 봇" 이라는 지름길을 배웠을 가능성. 실제 자동화는
이벤트 루프에서 시각이 나오므로 그 지름길이 통하지 않는다.

### B-5. 계획했던 Pointer 필드가 구현되지 않았다 · **코드**

`docs/행동데이터앞으로할것.md` §4.2 (2026-07-17) 가 14개 필드를 규정했다.

```
계획   seq · event_type · t_ms · x · y · x_normalized · y_normalized
       pointer_type · pointer_id · is_primary · buttons
       pressure · width · height · target_role

실제   type · object_id · x · y · timestamp_ms          ← 5개
모델   trajectory-only 2.3
```

`pointer_type`·`pressure`·`width`·`height`·`buttons`·`is_primary` 누락.
계획서에도 없는 것 둘을 추가로 제안한다 — `isTrusted`(JS 합성 이벤트 식별),
`getCoalescedEvents()` 개수(실제 브라우저 없이는 못 만드는 값).

**B-4 와 직결된다.** `(x, y, 시각)` 은 공격자가 마음대로 만드는 값이라
거기서만 계산한 특징은 원리적으로 따라잡힌다. 궤적 밖 신호가 없으면
"사람처럼 푸는 봇"에 대한 구조적 방어가 없다.

## C. 데이터 수집 — 진행을 막는 것

### C-1. 배포본에 참여자 코드가 아직 없다 · **실측**

```
배포본 VerifyRequest: [client_signals, duration_ms, events, pow_nonce,
                       selected_object_ids, session_id]
participant_id 배포됨: False
```

`sw-captcha 5dbee2e` 에 병합돼 있지만 미배포. 지금 수집하면 `?participant=`
코드가 무시되고 탭마다 다른 사람으로 잡힌다. **참여자별 FRR 이 핵심 지표라
이 상태로 모으면 헛돈다.**

### C-2. 허니팟이 채점 이전에 차단한다 · **실측**

전 객체를 제출한 12건이 12/12 허니팟 차단됐고, 모델까지 가지 않았다.
차단은 옳다. 다만 **허니팟을 집은 것은 확정 봇이고 그 궤적이 가장 값진
라벨 데이터인데 버려진다.** 채점 후 차단으로 순서만 바꾸면 사용자 영향 0으로
표본을 얻는다. 민서님 게이트라 임의로 바꾸지 않고 테스트로 고정만 해뒀다.

### C-3. 학습용 뷰가 새 스키마에 없다 · **실측**

`ai_training_dataset` 은 VIEW 인데 `SHOW VIEW` 권한이 없어 정의를 못 읽었다.
`catchap_ai` 에 미생성. 학습 경로 전용이라 수집·서빙에는 영향 없지만,
**재학습을 시작하려면 필요하다.**

## D. 인강 승급 — 관측이 안 되는 것

### D-1. `SUSPICION_SESSION_CONFLICT = 5` 가 임계의 절반이다 · **코드**

```python
SUSPICION_SESSION_CONFLICT = 5
BOT_SUSPICION_THRESHOLD    = 10     # 기본값
SESSION_TTL_SEC            = 30
```

409 는 "이어보기" 를 누르기 **전** 단계에서 난다. 즉 정상적인 기기 이동이나
30초 이내 새로고침이 그대로 +5 다. **두 번이면 캡차가 뜬다.**

그리고 이건 추측이 아니라 기존 코드가 이미 정상이라고 선언해 둔 동작이다.

```python
# RATE_TAKEOVER_PER_HOUR = 30
# 정상 사용(새로고침·기기 이동)은 시간당 수 회를 넘지 않는다.
```

**"시간당 수 회" 중 2회면 임계 도달이다.**

### D-2. 관측할 트래픽이 없다 · **하지영님 실측 인용**

```
최근 7일 학습한 학생   6명
최근 7일 진도 갱신     11건
현재 의심도 > 0        0건
```

`record` 모드를 켰지만 신호가 안 쌓인다. 가중치(3/5/4)·임계값(10)은 근거 없는
출발점인 채로 남아 있다. 시나리오 실행이 유일한 교정 경로다.

## E. 문항 풀

### E-1. 보기 2개 문항이 다수 있다 · **이전 측정(2026-07-29), 재확인 못 함**

당시 `captcha_ms` 조회로 **438개 문항이 보기 2개 = 찍어도 50% 통과**로 집계됐다.
지금은 `captcha_ms` 접근 권한이 없어 재확인하지 못했다. 수치가 바뀌었을 수 있다.

문제를 실제로 푸는 능력은 "사람처럼 움직이는 봇"에 대한 몇 안 되는 구조적
방어인데, 보기가 2개면 그 방어가 절반으로 깎인다.

## F. 확인하지 못한 것 (권한 없음)

정직하게 모른다고 적는다.

- **캡차 배포본의 `.env` 실제 값** — `ALLOWED_ORIGINS`, `HONEYPOT_COUNT`,
  `BEHAVIOR_*`. A-2 는 실측(엉뚱한 Origin 이 201)으로 확인했지만 설정값 자체는
  못 봤다. 기본값은 각각 `*`, `1` 이다.
- **`captcha_ms` 내용** — 문항 풀 현황, 배치·세션 원시 데이터. E-1 재확인 불가.
- **배포된 캡차의 정확한 커밋** — `participant_id` 부재로 `5dbee2e` 이전인 것만
  확인했다.
