# 최종 발표 — 이상 행동 감지

조성원 · 발표 2026-08-19 · 10분 기준 (슬라이드 11장)

> 각 장의 **말할 내용**은 그대로 읽어도 되는 문장으로 썼다. 숫자는 전부 실측이다.

---

## 1. 캡차를 통과하는 봇을 어떻게 잡나

**말할 내용**

인강 사이트의 가장 흔한 부정은 대리 시청입니다. 자동화가 강의를 틀어놓고 중간 확인
절차를 대신 통과합니다.

캡차는 **"무엇을 풀었는가"** 를 봅니다. 그런데 이미지 인식은 이제 쌉니다. 멀티모달
모델에 이미지와 문항을 넣으면 학습 없이 답이 나옵니다.

그래서 저는 **"어떻게 풀었는가"** 를 보기로 했습니다. 답이 맞아도 **푸는 동작이
사람의 것이 아니면** 걸러내는 층입니다.

---

## 2. "이상 행동"을 정의하는 것부터가 문제다

**말할 내용**

봇을 정의하려면 먼저 사람을 정의해야 합니다. 그런데 사람의 마우스 움직임에는
정답이 없습니다. 빠른 사람, 느린 사람, 트랙패드 쓰는 사람이 다 다릅니다.

그래서 규칙으로 못 쓰고 **데이터로 배워야** 했습니다. 사람 2만 건, 봇 1만 3천 건에서
궤적 특징 50개를 뽑아 학습시켰습니다.

```
속도 · 가속도 · 저크(가속도 변화율)
방향 전환 횟수 · 멈춤 횟수 · 미세 이동 비율
목표 초과 후 되돌림 · 종점 보정 시간
간격의 자기상관 · 타이밍 엔트로피 · 공간 엔트로피
```

두 갈래로 나눠 각각 학습시키고, **둘 중 낮은 점수**를 씁니다. 한쪽만 이상해도
위험으로 잡히게 하기 위해서입니다.

---

## 3. 사람과 봇은 실제로 이렇게 다르다

**말할 내용**

학습 데이터에서 실제로 갈린 특징들입니다.

| 특징 | 사람 | 봇 |
|---|---:|---:|
| 방향 전환이 있는 비율 | **88%** (평균 4.9회) | 47% (2.0회) |
| 멈춤이 있는 비율 | **98%** (평균 24.6회) | 59% (9.4회) |
| 목표를 지나쳤다 되돌린 비율 | **47%** | 19% |
| 종점에서 보정한 비율 | **39%** | 23% |

사람은 **망설이고, 지나치고, 되돌립니다.** 프로그램은 목표를 향해 곧게 갑니다.

이게 직관적으로도 맞는 이야기라 처음에는 여기서 끝날 줄 알았습니다.

---

## 4. 그런데 궤적만으로는 부족하다 — 4계층으로 봅니다

**말할 내용**

궤적은 흉내낼 수 있습니다. 그래서 네 층을 함께 봅니다.

**① 궤적** — 앞 장의 50개 특징

**② 타이밍의 구조** — 사람은 멈췄다가 다시 움직일 때 관성이 남습니다. 프로그램은
멈추고 정확히 다시 출발합니다. 이걸 `stop_go` 패턴으로 따로 잡습니다.

**③ 전송 방식** — 이벤트를 200ms마다 서버로 보내는데, **긴 궤적을 마지막에 한 번에
몰아 보내면** 브라우저에서 실시간으로 만들어진 게 아닙니다. 클라이언트 시각은
위조할 수 있지만 **서버가 받은 시각은 못 속입니다.**

**④ 실행 환경** — `navigator.webdriver`, 헤드리스 UA, 언어 설정 없음, CPU 코어 0.
자동화 브라우저의 순정 흔적입니다.

```
①  무엇을 그렸나
②  어떻게 멈추고 움직였나
③  언제 서버에 도착했나      ← 위조 불가
④  어떤 환경에서 왔나
```

**③이 핵심입니다.** 클라이언트가 보낸 값을 다시 믿지 않고, 서버가 보관한 것으로만
채점합니다.

## 5. 함정 하나 — "이상"을 규모로 재고 있었다

**말할 내용**

여기서 큰 결함을 하나 찾았습니다.

특징이 **세션 전체의 합계**였습니다. 이벤트 수, 총 시간, 총 이동 거리. 그런데 이 값들은
드래그를 여러 번 하면 그냥 커집니다.

그래서 **자로 그은 완전한 직선도 다섯 번 반복하면 사람 판정**을 받았습니다.

```
직선 궤적 · 1회 드래그   →  0.0296   차단
직선 궤적 · 5회 드래그   →  0.9996   통과
```

**같은 궤적입니다.** 공격자에게 "여러 번 끌기"는 반복문 한 줄입니다.

드래그마다 따로 채점하고 중앙값을 쓰도록 고쳤습니다. 그러자 가려져 있던 것도
드러났습니다 — 다중 드래그 사람이 통과하던 것은 **모델이 알아봐서가 아니라 합계가
부풀어서**였습니다.

## 6. 함정 둘 — 이상하지 않게 만드는 공격

**말할 내용**

더 어려운 상대가 있습니다. **모델을 보고 "이상하지 않은 점"을 찾아내는 공격자**입니다.

저희 레드팀은 봇 궤적을 무작위로 만들어 뚫리는 걸 세는 방식이었습니다. 그런데 같은
모델에 시드만 바꿔 여섯 번 돌려보니 결과가 이랬습니다.

```
회피 28건 · 0건 · 21건 · 18건 · 1건 · 17건
```

**0건이 나온 시드로 봤으면 "완벽하다"고 발표했을 겁니다.**

실제 공격자는 처음부터 다시 뽑지 않습니다. 먹힌 걸 남기고 그 주변을 팝니다.
그래서 진화 탐색으로 다시 만들었습니다.

```
무작위 스윕   0.7%
진화 탐색     47%     ← 실제 회피율
```

**우리 측정 도구가 공격을 60배 과소평가하고 있었습니다.**

---

## 7. 막는 방법 — 판별이 아니라 밀도

**말할 내용**

이 공격이 어려운 이유는, 그 점들이 **모델이 "사람"이라고 답하는 영역 안**에 있기
때문입니다. 임계값을 어디에 두든 그 안쪽입니다.

그런데 **모델이 사람이라고 보는 영역이 실제 사람이 차지하는 영역보다 훨씬 넓습니다.**
공격자가 찾은 점은 그 넓은 빈 자리에 있습니다.

그래서 질문을 하나 더 던졌습니다 — **"실제 사람들 근처에 있는가"**

| | 사람 데이터까지 거리 |
|---|---:|
| 진짜 사람 | **2.0** |
| 처음 보는 사람 | **2.0** |
| 공격자가 찾은 점 | **5.6** |
| 일반 봇 | 8.6 |

**처음 보는 사람도 2.0입니다.** 사람은 누구든 사람들 근처에 있고, 공격자의 점은
2.8배 멀리 있습니다.

그리고 레드팀이 찾아낸 약점 2,554건을 학습에 넣어봤습니다. 회피율이 크게 떨어졌는데,
**나중에 그 데이터가 학습 금지였다는 것을 발견했습니다.** 매니페스트에
`detector_training_forbidden: true` 가 박혀 있습니다. 그 데이터로 학습하면 그것으로
회피율을 잴 수 없게 되기 때문입니다. **그 후보는 폐기했습니다.**

## 8. 결과

**말할 내용**

후보 여섯을 같은 자로 쟀습니다. 회피율은 진화 레드팀 30세대(마지막 5세대 평균),
사람 오탐은 메인 캡차 수집분에서 참여자를 한 명씩 빼고 잰 값입니다.

| 모델 | 회피율 | 전체 오탐 | 최악 참여자 | 재현 |
|---|---:|---:|---:|:---:|
| 현재 배포본 | **74.7%** | 7.3% | 27.3% | ✅ |
| scale_pixel | 7.1% | 3.3% | 10.6% | ❌ |
| 약점셋 학습본 | 6.6% | 4.1% | 12.1% | ⛔ 규칙 위반 |
| 크기 정규화본 | 10.8% | 4.5% | 15.2% | ❌ |
| surface_aware | 92.6% | 1.2% | 3.2% | ✅ |
| **drag_unit** | *측정 중* | **1.6%** | **3.2%** | ✅ |

```
기준  회피율 ≤10%  ·  전체 오탐 ≤2%  ·  최악 참여자 ≤5%
```

**맞바꿈입니다.** 회피율이 낮은 모델일수록 사람을 더 막습니다. 8/05 판에
"사람 오탐은 오히려 줄었다, 맞바꿈이 아니다" 라고 적었던 것은 철회합니다.

**현재 배포본이 74.7% 뚫린다는 것이 이 프로젝트의 가장 중요한 숫자입니다.**
개선이 필요하다는 근거이고, 동시에 지금까지의 방어를 과신하면 안 된다는 근거입니다.

실제로 잡은 사례도 있습니다. 제가 브라우저 자동화로 캡차를 풀어봤는데, **답을 맞혔는데도**
이런 응답이 왔습니다.

```json
{"success": false, "step_up": true, "risk_level": "suspicious"}
```

**정답은 맞았지만 푸는 동작이 사람의 것이 아니었습니다.** 이 층이 하는 일이 정확히
이겁니다.

## 9. 못 잡는 이상 행동

**말할 내용**

무엇을 못 잡는지도 측정했습니다. 이게 없으면 방어를 과신하게 됩니다.

| | 왜 못 잡나 |
|---|---|
| **사람 대행 서비스** | 진짜 사람이 풉니다. 행동으로는 원리적으로 불가 |
| **시각 인식 봇** | 답을 맞히는 건 막지만, 동작을 사람처럼 만들면 뚫립니다 |
| **재생 조작** | 배속·탭 숨김은 **포인터를 아예 안 건드립니다** |

세 번째가 인강 사이트에서 제일 흔한 부정인데, **행동 판별이 원리적으로 못 봅니다.**
진짜 사람이 앉아 있고 자동화는 재생만 제어하기 때문입니다.

다만 싸게 잡힙니다. 서버가 이미 받고 있는 **진도 증가량과 실제 경과 시간의 비율**만
보면 됩니다. 16배속으로 파밍하면 비율이 16이 되고, 공격자가 못 속입니다 — 천천히
보내면 파밍 자체가 안 되니까요.

**이건 다음 과제로 남깁니다.**

## 10. 승급은 안 했다 — 이유가 중요합니다

**말할 내용**

*8/06 갱신: 8/05 판은 "성능은 통과하는데 증명할 데이터가 없다" 였습니다. 다시 재보니
성능도 통과하지 못합니다. 대신 무엇이 막고 있는지는 훨씬 정확해졌습니다.*

| 항목 | 기준 | 현재 |
|---|---|---|
| 미지 공격 회피율 | ≤10% | 배포본 **74.7%** ❌ |
| 전체 사람 오탐 | ≤2% | 배포본 **7.3%** ❌ |
| 최악 참여자 오탐 | ≤5% | 배포본 **27.3%** ❌ |
| 검증용 참여자 | 5명 | **5명** ✅ (8/06 수집 410건) |
| 봉인 검증 데이터 | 필요 | **있음** ✅ (sw·ms 189건, 미개봉) |

**8/05 대비 데이터 쪽 두 항목은 해결됐습니다.** 하루에 5명 410건을 모았고, 봉인은
결과를 보기 전에 소금값으로 갈랐습니다.

**막고 있는 것은 이제 모델입니다.**

```
두 관문을 같이 넘는 후보   scale_pixel 하나
                          그런데 어떻게 만들었는지 기록이 없어 재현 불가

재현 가능한 후보 두 개     회피율에서 탈락 (92%대)
                          원인은 임계값 — 사람을 통과시키려 문을 열면 봇도 들어옴
```

**이게 이 프로젝트의 정직한 현재 상태입니다.**

7월 30일에 **결과를 보기 전에** 기준을 못박아 뒀습니다. 그리고 33%라는 나쁜 숫자를
보고도 고치지 않았습니다. 지금 기준을 만족시키려고 고치면 그 기록이 의미를 잃습니다.

## 11. 3주 동안 배운 것

**말할 내용**

이 프로젝트에서 숫자를 네 번 뒤집었습니다.

```
"오탐률 0.11%"        → 실제 화면에서 33%      학습 데이터가 다른 화면이었다
"오탐률 1.5%"         → 처음 보는 사람 4.5%    답을 본 데이터에서 쟀다
"이건 못 막는다"       → 3.3%                  레드팀이 60배 약했다
"검증 한 번도 안 받음"  → 이미 받았음            파일 이름만 보고 판단했다
```

**네 번 다 우리에게 유리한 쪽으로 틀렸습니다.**

이상 행동 감지에서 제일 어려운 건 이상을 잡는 게 아니라, **잘 잡고 있다는 착각을
걷어내는 것**이었습니다. 그래서 이번에 만든 것 중 절반이 측정 도구입니다.

봉인 데이터 검증기는 **홀드아웃으로 표시된 데이터 세 개가 사실 학습 데이터**라는
것도 찾아냈습니다. 그대로 채점했으면 학습 데이터로 시험 본 셈이었습니다.

## 예상 질문과 답

**"실서비스에서 봇을 막고 있나요?"**
아직 아닙니다. 점수만 기록하는 상태이고 위젯 연동이 남았습니다.

**"오탐률이 몇 퍼센트인가요?"**
참여자가 2명이라 숫자를 말씀드릴 수 없습니다. 2명 기준 1.2~4.5%인데, 그 폭 자체가
표본 부족이라는 뜻입니다.

**"3.3%는 믿을 수 있나요?"**
저희가 만든 가장 강한 공격자 기준입니다. 더 강한 공격자를 만들면 올라갈 수 있습니다.
다만 이전 도구가 60배 과소평가했던 것을 감안하면 지금 숫자가 훨씬 정직합니다.

**"규칙 기반으로는 안 되나요?"**
사람의 움직임에 정답이 없어서 규칙으로는 못 씁니다. 다만 **명백한 하한**은 규칙으로
씁니다. 예를 들어 드래그당 중간 이동이 2개 미만이면 사람이 아닙니다 — 사람은 최소
2.3개, 중앙값 11개인데 순간이동 봇은 정확히 1개입니다.

**"왜 기준을 낮추지 않았나요?"**
7월 30일에 결과를 보기 전에 정했습니다. 숫자를 보고 기준을 고치면 그 기준이 의미를
잃습니다.
