# 조준 구간이 실사용에서 듣는다 — 전환·측정·남은 것

조성원 (행동 AI) · 2026-08-12

---

## 한 장 요약

로그인 캡차를 우리 캡차로 바꿨고, 실사용에서 조준 구간이 처음으로 쌓이기 시작했다.
그 데이터로 조준 전략이 실제로 듣는지 확인했다.

```
                  재사용    변형0.01   변형0.02
드래그만          100.0%     44.7%      7.7%
조준+드래그       100.0%     95.0%     64.7%
```

같은 사람 오탐 예산(3%)에서 잰 값이다. **변형 재생이 44.7% → 95.0%.** 이 계열이
`replay_warp` 로, 승격을 막고 있는 항목이다(기준 ≤5%, 현재 21~73%).

승격은 아직 멀다 — 네 기준이 미달이고 전부 데이터가 병목이다(§5).

## 1. 무엇이 바뀌었나

아침까지 실사용 진입점에서 봇을 거르는 장치가 하나도 없었다.

```
로그인 5회 실패   캡차는 떴지만 프론트 자체 구현 — 원시 궤적을 안 남김
강의 시청        LLM 문제형 캡차 — 정답만 봄, 행동 안 봄
이상행동 감지     카운터만 쌓이고 캡차 발급 없음
우리 캡차        독립 페이지에서만 — 제품 어디서도 안내하지 않음
```

지금은 로그인 캡차가 우리 것이고 궤적·조준이 실사용에서 쌓인다.

```
프론트  DragObjectCaptcha  →  captcha.catchap5.com/api/captcha/*
켜는 값 VITE_LOGIN_CAPTCHA=catchap   (프론트 .env.production 이 정본)
백엔드  captcha_session_id 가 오면 POST /api/verify-token 으로 검증
```

**iframe 이 아니라 API 로 붙였다.** 캡차 서버 `ALLOWED_ORIGINS` 에 자기 자신이 없어
iframe 안에서 부르면 Origin 이 `captcha.catchap5.com` 이 되어 403 이 난다. `www` 에서
부르면 201 이고 CORS 도 www 로 열려 있다.

```
Origin www.catchap5.com       201
Origin captcha.catchap5.com   403 Origin not allowed
Origin evil.example.com       403
```

부수적으로 UI 를 우리가 쥐게 됐다. iframe 은 높이 760px 고정이라 짧은 화면(실측
1000x478)에 안 들어간다.

## 2. 조준 효과 — 재현 방법

```
① 운영 배치를 연구 도구 모양으로 꺼낸다
   .venv/bin/python tools/export_aim_from_production.py \
       --password-file <file> --since '2026-08-12 04:29:00' \
       --out data/interim/aim_production_20260812.jsonl

② 드래그만 / 조준+드래그 두 벌로 재생 공격 검출을 잰다
   (scratchpad/aim_replay_gain.py — 회전 불변 비교기, 오탐 예산 3% 고정)
```

첫 실행에서 경로 길이가 연구 예측과 맞았다.

```
예측(08-10 연구)   중앙 33점 · 31점 이상 57.3%
실사용(08-12)      중앙 34점 · 31점 이상 57.1%
```

31점은 변형 재생 검출이 1.4% → 96.8% 로 올라가는 경계다. 그 경계를 실사용 궤적이
절반 넘게 넘긴다.

**왜 조준이 특히 유용한가:** 문항마다 객체 위치가 달라 훔친 조준 자취는 재사용이
안 된다. 드래그는 "A에서 B로" 라 훔친 걸 비틀어 쓸 수 있지만 조준은 매번 다른 곳으로
새로 가야 한다.

## 3. 전환에서 잡은 함정 다섯

전부 "코드는 맞는데 안 되는" 종류였다. 공통 원인은 **실제 코드가 만드는 요청이 아니라
손으로 쓴 payload 로 검증**한 것이다. 마지막에 esbuild 로 모듈을 번들해 진짜 함수를
돌리고 나서야 잡혔다.

| | 증상 | 원인 |
|---|---|---|
| ① | 정답인데 캡차 실패 | 배치 이벤트에 `seq` 누락 → 전량 422 → "행동 없는 사용자"로 보여 위험도 게이트에 걸림 |
| ② | 같은 증상 | `client_signals` 를 `{}` 로 보냄 → `automation_score()` 에서 "신호 없음"과 "봇 아님"이 구분 안 됨 |
| ③ | 정답인데 캡차가 계속 다시 뜸 | `public_login` 이 `ops_login` 에 위임할 때 `captcha_session_id` 를 빠뜨림 → 게이트가 Guard 토큰을 못 알아봄 |
| ④ | 조준이 하나도 안 쌓임 | 위젯이 조준을 `/collect-aim`(로컬 수집기)으로 보냄 — 실서비스엔 그 수집기가 없음 |
| ⑤ | submit 유실 7.6% → 18.6% | 조준을 배치 큐에 넣자 `flushBehavior` 의 3회 배수 제한에 걸림. 제출 뒤에도 포인터가 움직이면 큐가 계속 늘어 `submit` 이 안 나감 |

③은 배포 확인 방법도 함께 남긴다. **워크플로 성공은 배포 확인이 아니다** — 태그 갱신과
파드 반영 사이에 3분 시차가 있었다. 확인 조건은 **그 변경에만 있는 값**으로 잡아야 한다
(`current)return` 같은 흔한 패턴으로 잡았다가 옛 번들에 걸려 오보를 냈다).

## 5. 승격까지 — 기준 대비

> **이 절은 0812 밤 기준이다. 이후 진행은
> [`AIM_CLASSIFIER_DECISION_20260812.md`](AIM_CLASSIFIER_DECISION_20260812.md) 를 본다.**
>
> 0813 에 바뀐 것 셋:
> - `Human FRR 16.7%` 의 원인이 규명됐다. 거부권 문턱이 학습 사람의 **드래그** 밀도
>   하위 2% 인데 채점은 세션 단위로 들어간 것이다(13배 차이). 세션 단위로 읽으면
>   실사용 오탐이 18.9% → 9.7% 가 된다. 좌표계도 의심해 정규화 좌표로 다시 맞춰봤지만
>   **효과 없었다**(9.9% → 9.7%).
> - 조준을 넣은 분류기를 만들어 배포했다(`aim_overall3_20260812`). 실사용 재요구율이
>   39.7% → 0.0% 가 됐다(23건 기준, 표본은 아직 작다).
> - **승격 기준을 못 넘긴 채로 `active` 로 켰다.** 미지 계열 41.3%(기준 10%), 특정
>   참가자 14.1%(기준 3%). 그 판단의 근거와 되돌리는 법은 위 결정 문서에 있다.
>
> 아래 표는 그 시점의 기록으로 남긴다.

| 기준 | 목표 | 현재 | |
|---|---|---|---|
| 미지 Bot 최악 ASR (LOFO) | ≤10% | 54~73% | ❌ |
| `replay_warp` ASR | ≤5% | 21~73% | ❌ |
| 브라우저 자동화 ASR | ≤10% | 20.7% | ❌ |
| Human FRR | 실험 ≤3% / 배포 ≤1% | 16.7% | ❌ |
| 알려진 Bot ASR | ≤5% | 1.4% | ✅ |
| 정확히 같은 궤적 replay | ≤1% | 0% | ✅ |

`Human FRR 16.7%` 는 실사용 402건에서 잰 값이다. 그중 11.2%p 가 거부권(veto)이 0점을
박은 것이다 — 문턱이 드래그 단위 분포에서 잡혔는데 채점은 세션 단위로 들어간다.
계산을 세션 단위로 고쳤지만(`tools/train_density_veto.py`) 값은 아직 안 정했다.
LOFO 를 다시 재야 정해진다.

`브라우저 자동화 20.7%` 는 궤적이 아니라 `client_signals`(webdriver·headless)로 잡는
층이다. 그 값이 실제로 저장되면 풀릴 가능성이 크다.

### 필요한 데이터

```
실험 기준(오탐 3%)   사람당  99세션 × 8명 =   792
배포 기준(오탐 1%)   사람당 299세션 × 8명 = 2,392
현재                 최대 195세션 (한 명)
```

오탐 0건일 때 95% 신뢰로 기준을 넘지 않음을 보이는 데 필요한 수다. 참가자 단위
정책이라 사람마다 그만큼 필요하다.

승급 캡차 설계상 오탐의 대가가 "차단" 이 아니라 "캡차 한 번 더" 이므로 3% 기준으로
가는 근거는 있다(`RISK_TRIGGERED_CAPTCHA_PLAN.md` §0). 다만 그건 정책 결정이다.
