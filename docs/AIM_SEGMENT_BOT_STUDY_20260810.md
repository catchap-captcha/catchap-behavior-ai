# 조준 구간 봇 설계와 판정 가능성 — 2026-08-10

조성원 · 사람 4명 582구간 · 봇 4계열 각 400건

## 왜 했나

드래그(12점 / 650ms)는 리플레이 계열에 대해 이미 한계가 확인된 표면이다.
**사람끼리도 경로 유사도가 1.0000 에 닿기 때문에** 사람 변동이 이미 넘어버린 선을
모델이 지킬 수 없다. 조준 구간은 같은 포인터의 한 순간 앞이고, 측정해보니
16점 / 1049ms — 점이 4개, 시간이 1.6배 많다. **해상도가 늘면 판정이 되는가**가 질문이었다.

## 사람의 조준은 이렇게 생겼다

```
peak_at         0.000    가장 빠른 순간이 첫 걸음
slow_fraction   0.625    여정의 62%를 최고속도의 1/5 미만으로 기어간다
straightness    0.862
speed_cv        1.190
submovements    1
```

**확 날아와서 오래 기어간다.** 손이 이미 움직이는 상태로 들어와 목표 근처에서 길게 감속한다.
매끄러운 이징 곡선은 정확히 반대(peak_at≈0.5)라, 여기가 시판 도구가 틀리는 지점이다.

## 봇 4계열

공격자는 **객체 위치를 안다**. 양보가 아니라 사실이다 — 좌표가 챌린지 응답에 실려 온다.
그래서 조준은 목적지가 알려진 점-대-점 이동이고, 위조할 것은 중간의 움직임뿐이다.

네 계열 모두에게 다음을 **일부러 공짜로 줬다**: 진짜 사람 조준과 같은 시작점·목표,
사람 분포에서 뽑은 지속시간, 위젯의 40ms 캡처 스로틀. 봇이 엉뚱한 시간을 골라서
잡히는 방어는 시험된 게 아니다.

| | 설계 | 성격 |
|---|---|---|
| `A_linear` | 직선 등속 | 바닥 |
| `B_eased` | 베지어 + 최소저크 이징 + 떨림 | 시판 humanized-cursor 가 하는 것 |
| `C_ballistic` | 탄도 투척 + 교정 하위운동 | 위 표를 읽고 구현한 공격자 |
| `D_replay` | 진짜 사람 조준을 회전·크기변환해 재사용 | **가장 강함. 드래그를 무너뜨린 그것** |

### 만들면서 잡은 생성 버그 4개

모델을 만들기 **전에** 계열별 단일 특징 AUC 를 먼저 쟀다. 0.98 을 넘으면 방어의 승리가
아니라 생성기 버그로 취급한다는 규칙이다. 실제로 넷이 걸렸다.

| 증상 | 원인 | 고침 |
|---|---|---|
| `interval_cv` 0.966 | 봇이 50ms 로 균일하게 뿜음 | 사람 간격 풀에서 부트스트랩 |
| `turn_abs_mean` 0.878 | 떨림 0.003 고정 — 사람 걸음의 62%가 짧은 구간이라 각도가 튐 | 0.0005 로. 해시만 깨면 충분하고 **그게 더 강한 공격** |
| 점 12개 (사람 16) | 지속시간 재조정이 스로틀에 걸려 궤적을 솎아냄 | 원본 타이밍 그대로 재생 |
| 13% 좌표 잘림 | 배율이 0.15~4.9배까지 벌어져 무대 밖으로 | 이동 길이에 맞는 원본을 골라 씀 |

넷 다 **방어가 내 실수를 탐지하고 있었던** 경우다. 고친 뒤 `D_replay` 의 최고 단일 특징은 0.663.

## 결과

### ① 합성된 움직임은 아주 잘 잡는다

계열을 학습에 넣었을 때의 교차검증 AUC:

```
A_linear     1.000        B_eased      0.997
C_ballistic  0.999        D_replay     0.516   ← 동전 던지기
```

### ② 리플레이는 낱개 판정으로 **못 잡는다** — 신호가 없다

`D_replay` 는 학습에 **넣고 봐도** AUC 0.516 이다. 특징이 부족한 게 아니라
구별할 것이 없다. 사람 궤적을 회전시킨 것은 사람 궤적이다.

**드래그와 같은 결론이고, 사람을 더 모아도 바뀌지 않는다.** 공격은 사람 수가 늘어도
약해지지 않기 때문이다.

### ③ 빈 구석 현상이 그대로 재현됐다

계열 하나를 빼고 학습한 뒤 그 계열로 시험(leave-one-family-out):

```
뺀 계열        ASR      ← 사람 오탐 6.2% 고정
A_linear     100.0%     ⚠️ 단일 특징 AUC 1.000 로 잡히는 가장 멍청한 봇
B_eased       53.2%
C_ballistic   83.2%
D_replay      95.2%
```

`A_linear` 100% 는 오타가 아니다. 완벽히 균일한 직선은 어느 계열도 방문하지 않는
구석이고, 트리는 외삽하지 않는다. 드래그 표면에서 진단한 것과 같은 병이다.

밀도 거부권을 붙이면 크기 의존 특징을 뺐을 때 `A_linear` 이 100.0% → 7.2% 로 내려간다.
다만 `C_ballistic` 은 오히려 나빠지는데, **사람 121구간으로는 밀도 모델의 표본이 모자라**
시험 사람이 영역 밖으로 나가 문턱을 밀어올리기 때문이다. 드래그 때는 3명 349건이었다.

### ④ ★새로 알아낸 것 — 궤적 지문은 조준 구간에서 **살아난다**

낱개 판정이 아니라 **궤적끼리 닮았는지** 보는 축. 드래그에서는 사람끼리 1.0000 이 나와
죽은 축이었다. 회전·크기를 맞춘 뒤(프로크루스테스) 다시 쟀다:

```
사람 vs 다른 사람 조준   중앙값 0.369 · p95 0.877 · 최대 0.970
리플레이 vs 그 원본      중앙값 0.991 · p5  0.961 · 최소 0.884

분리 AUC 0.999
리플레이 95% 를 잡는 문턱에서 무고한 쌍 오탐 0.25%
```

**드래그와 정반대다.** 조준 구간은 궤적을 개별 식별할 만큼의 모양을 담고 있다.

기존 비교기(`NormalizedPathComparator`)로는 AUC 0.507 로 죽어 보였는데,
축별로 정규화해 **회전 정보를 날리기 때문**이다. 회전을 맞추면 0.999.

### ⑤ 다만 공격자는 일그러뜨려 피할 수 있다

양 끝(시작점·객체)을 고정한 저주파 변형. 실제 공격자가 지켜야 하는 제약이다.

```
변형크기   원본과 유사도   유사도 회피   낱개 통과   둘 다 통과
 0.000        1.0000        0.0%      94.0%      0.0%
 0.005        0.9560       56.2%      79.8%     40.0%
 0.020        0.8525       97.3%      59.8%     57.8%
 0.080        0.5485      100.0%      47.3%     47.3%
```

10px(0.02) 변형이면 유사도를 97% 피하면서 낱개 판정도 60% 통과한다. **협공이 닫히지 않는다.**

### ⑥ 변형 계열을 학습에 넣으면? 본 것만 잡는다

사인 변형을 학습에 넣고, **다른 방식**(구간별 시간왜곡 + 어깨점)으로 시험:

```
                    본 계열(사인)   미지 계열(시간왜곡)
사인 변형 학습 안 함     60.8%           16.8%
사인 변형 학습에 넣음     2.5%           20.7%
```

본 계열은 60.8% → 2.5% 로 무너지지만 **미지 계열은 오히려 조금 나빠진다.**
변형 방식 사이에 일반화가 없다. 늘 그랬듯 모델은 본 것만 잡는다.

## 결론

**조준 구간은 리플레이 문제의 해답이 아니다.** 낱개 판정으로는 신호가 아예 없고(AUC 0.516),
이건 사람을 50명 모아도 바뀌지 않는다.

**그러나 값어치가 없지는 않다.** ④가 새로운 것이다 — 조준 구간은 드래그가 못 하던
**궤적 지문**을 가능하게 한다(AUC 0.999, 무고한 쌍 오탐 0.25%). 방어의 성격이 바뀐다:
"이 궤적이 봇인가" 가 아니라 "이 궤적을 전에 본 적 있는가" 다.

## 다음에 할 것

1. **사람을 더 모은다 — 단, ④를 확인하기 위해서다.** 위 사람-쌍 유사도는 전부
   `sw` 한 명 안에서 잰 것이다. 같은 사람의 조준끼리가 서로 다른 사람보다 닮았을 테니
   방향은 방어에 유리하지만, 확인은 필요하다.
2. **`sw` 로는 더 모으지 않는다.** `sw` 는 봉인 대상자(ms·sw)다. 봉인된 사람의 데이터로
   개발하면 봉인을 열 때 같은 사람이 양쪽에 있게 되고, 한 번뿐인 그 기회가 오염된다.
   지금 147건은 파이프라인 점검용으로 두고, 학습용은 jy·p4·p5 나 새 참가자로 받는다.
3. **지문 축은 이력 저장이 필요하다.** 낱개 판정과 달리 이전에 본 궤적과 대조해야 한다.
   `replay_detector` 가 이미 DB 에서 이력을 읽으므로(`predict.py:114`) 자리는 있지만,
   세션 안이 아니라 세션을 넘는 라이브러리가 필요하다 — 설계 결정 사항이다.
4. **비교기를 회전 불변으로 바꿔야 한다.** 지금 것은 회전을 못 본다(0.507 vs 0.999).

## 이 문서가 주장하지 않는 것

②③은 사람 1명일 때 얻은 **부정적 결과**다. 1명으로도 결론이 서는 이유는 공격이 사람
수에 따라 약해지지 않기 때문이고, 사람이 4명이 된 뒤에도 다시 재지 않았다 — 다시 재도
바뀌지 않는다.

④는 4명 582구간으로 확인했지만 **4명은 적다.** 오탐 0.040% 는 15,000쌍 중 6건이라,
10명쯤에서 흔들릴 수 있다. 방향은 확실하다(사람이 늘수록 좋아졌다). 승급 심사에
올리려면 기준 문서가 요구하는 규모가 따로 있다.

⑤⑥은 여전히 유효하고, 이것이 남은 구멍이다. 지문 축이 살아 있어도 공격자가 10px
일그러뜨리면 유사도를 97% 피하면서 낱개 판정도 60% 통과한다.
