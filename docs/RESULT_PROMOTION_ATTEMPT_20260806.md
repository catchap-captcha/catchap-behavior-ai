## 2. 정식 재학습을 했고, 실패했다

```
tools/run_formal_two_view_fusion.py
  fold ×5 → assemble → fit-lockbox-candidate
  --all-input-development --max-human-frr 0.01 --human-frr-policy per_participant
  human 20,234행 (레거시 20,066 + 오늘 168) · bot 13,300
  development_rows 33,534
```

**기록은 완비됐는데 회피율이 92.6% 로 배포본(74.7%)보다 나빠졌습니다.**

### 왜 나빠졌나 — 임계값이다

```
배포본           임계 0.99995
scale_pixel      임계 0.99979
surface_aware    임계 0.44890
```

오늘 수집분을 넣자 참여자별 FRR ≤1% 제약이 임계를 0.45 까지 끌어내렸습니다.
임계가 낮으면 봇이 그냥 통과합니다.

**임계가 내려간 이유가 핵심입니다.** 메인 캡차에서 모은 사람들의 점수가 원래 아주
낮습니다. 그 사람들을 1% 안에 넣으려면 문을 활짝 열 수밖에 없습니다.

```
7/31    메인 캡차에서 FRR 33.3%
8/06    그 사람들을 통과시키려면 임계를 0.45 로 내려야 함
        → 같은 현상의 다른 얼굴
```

**행을 더 넣는 것으로는 해결되지 않습니다.** 모델이 메인 캡차 사람을 높게 매기도록
학습 방식을 바꿔야 합니다. `tools/retrain_per_drag.py` 가 그 도구입니다 — 세션이 아니라
드래그 단위로 학습합니다.

## 5. 드래그 단위 학습도 해봤고, 실패했다

메인 캡차 사람이 낮게 매겨지는 근본 원인을 치려고 `tools/retrain_per_drag.py` 를
오늘 수집분(jy·p4·p5 246건)과 8/03 봇 298건으로 돌렸습니다.

```
세션 435건 · 드래그 991개 · 사람 3명 · 봇 248건

  빼놓은 사람   재학습 FRR   재학습 ASR   현재 FRR   현재 ASR
  jy              9.9%        0.0%        0.0%      21.4%
  p4             25.0%        0.0%        0.0%      21.4%
  p5             22.7%        0.0%       40.9%       2.0%
```

**봇은 완전히 막는데(ASR 0%) 처음 보는 사람을 10~25% 거부합니다.** 기준은 3% 입니다.

### 이건 예고된 실패다

```
collection_split.py 에 미리 적혀 있던 경고
  "8/03 측정: 사람 2명으로 재학습하면 처음 보는 사람 오탐이 10~22% 로 나빠진다"

오늘 실측
  9.9% · 25.0% · 22.7%
```

사람 3명에서 하나를 빼면 **학습에 2명**이 남습니다. 그 조건이 그대로 재현됐습니다.
새 발견이 아니라 사전에 기록해둔 값이 맞았다는 확인입니다.

### 그런데 도구 주석이 틀려 있었다

`retrain_per_drag.py` 는 "레거시 궤적에는 press/release 경계가 아예 없어서 드래그로
자를 수 없다" 고 적어두고 있었습니다. **사실이 아닙니다.**

```
레거시 800세션 검사
  드래그가 나오는 세션   800건 (100%)
  세션당 드래그          1개
  이벤트                pointerdown 800 · pointerup 740 · pointermove 135,806
```

**레거시 20,066행을 드래그 단위 학습에 쓸 수 있습니다.** 오늘 실패한 것은 접근법의
한계가 아니라 **2명분만 넣었기 때문**입니다. 주석은 고쳤습니다.

## 6. 재현 가능한 후보를 만들었다 — 그리고 방법론 결함을 찾았다

`tools/train_drag_unit_candidate.py` 를 새로 만들어 드래그 단위 학습을 정식화했습니다.
`retrain_per_drag.py` 가 people-starved 로 실패한 원인(레거시를 안 씀)을 고쳤습니다.

```
세션 41,598 (사람 20,298 · 봇 21,300) · 드래그 41,716 · 사람 그룹 50개
입력 해시 · 봉인 분할 · 제외 규칙 전부 reports/ 에 기록
```

### 결과 — 오탐은 통과, 회피는 탈락

| 모델 | 임계 | 회피율 | 전체 오탐 | 최악 참여자 |
|---|---:|---:|---:|---:|
| drag_unit (FRR 1% 보정) | 0.0122 | 92.5% | 1.6% | 3.2% |
| drag_unit (FRR 5% 보정) | 0.1499 | **83.5%** | 1.6% | 3.2% |

### 그런데 두 축을 다른 임계값에서 재고 있었다

```
회피율   모델에 저장된 임계값으로 측정
오탐     측정 시점에 다시 맞춘 동작점으로 측정
```

**같은 곡선 위의 두 점이 아닙니다.** 저장 임계가 낮은 모델은 회피율이 나쁘게, 오탐은
좋게 나옵니다. 8/06 표에서 `drag_unit` 이 오탐 1.6% 로 최고이면서 회피율 92.5% 로
최악이었던 것이 순전히 이 때문입니다.

```
scale_pixel   임계 0.99979   회피  7.1%
drag_unit     임계 0.01219   회피 92.5%
```

임계를 0.0122 → 0.1499 로 올리자 회피율이 92.5% → 83.5% 로 내려갔습니다. 같은 모델입니다.
`frr_candidate_compare.py` 상단에 경고를 박아뒀습니다.

### 임계를 더 올려도 안 되는 이유

진화 탐색이 찾아낸 최고 공격 점수를 보면 답이 나옵니다.

```
drag_unit_frr5    최고 공격 점수 0.9965   임계 0.1499
scale_pixel       최고 공격 점수 0.99998  임계 0.99979
배포본             최고 공격 점수 1.0000   임계 0.99995
```

**drag_unit 은 진화한 공격에 0.9965 를 줍니다.** 회피율을 10% 아래로 내리려면 임계를
0.99 근처까지 올려야 하고, 그러면 사람이 대량으로 막힙니다. 동작점 조정으로 풀 수
있는 문제가 아니라 **모델이 진화 공격을 못 가른다**는 뜻입니다.

## 7. 진짜 원인 — 메인 캡차 드래그가 너무 짧다

"55개 특징이 못 보는 것을 찾아라" 로 시작해서 다른 결론에 도착했습니다.

### 우리 봇이 전부 다른 화면 것이었다

```
레거시 기반 공격으로 재면    event_count AUC 1.000   ← 완벽 분리
메인 캡차 기반 공격으로 재면  최고 AUC   0.947       ← 훨씬 어려움
```

봇 학습 데이터 21,300건이 **전부 레거시 모양**(드래그당 107이벤트)입니다. 메인 캡차
드래그는 12이벤트입니다. **모델은 메인 캡차 모양의 봇을 한 번도 본 적이 없습니다.**

7/31에 사람 쪽에서 겪은 것과 같은 문제입니다.

```
7/31   모델이 메인 캡차 사람을 못 봄  →  FRR 33.3%
8/06   모델이 메인 캡차 봇을 못 봄    →  회피율 83.5%
```

### 신호는 이미 있다 — 모델이 안 쓸 뿐이다

메인 캡차 모양 공격으로 다시 재니 이 축들이 살아 있습니다.

| 특징 | AUC | 사람 | 봇 |
|---|---:|---:|---:|
| timing_entropy | 0.947 | 0.417 | 0.750 |
| normalized_speed_p90 | 0.914 | 0.0092 | 0.0032 |
| **pause_ratio** | 0.911 | 0.276 | **0.000** |
| **pause_count** | 0.909 | **3.0** | **0.0** |
| step_quantisation (새 후보) | 0.891 | — | — |

**사람은 드래그 중간에 3번 멈추고 봇은 한 번도 안 멈춥니다.** 생성기가 바꾸는 값
(curvature·jitter·time_power·duration_scale·turn_slowdown·coalesce_fraction·
frame_ms·late_correction)에 멈춤이 없기 때문입니다.

그리고 `pause_count`·`pause_ratio` 는 **이미 55개 안에 있습니다.** 새 특징이 필요한
게 아니라 모델에게 볼 이유를 준 적이 없었던 것입니다.

### 그런데 메인 캡차 모양 봇을 넣어 재학습해도 안 됐다

```
세션 47,598 (사람 20,298 · 봇 27,300 — 메인 캡차 모양 6,000 포함)
임계 0.000823 · 최악그룹 FRR 3.45% · 봇 ASR 50.98%
```

**학습에서 봤는데도 절반이 통과합니다.**

### 이유 — 재생 탐지기도 못 가른다

공격은 실제 사람 궤적 226개를 조금씩 변형한 것이라 사실상 재생입니다. 프로덕션에는
재생 탐지기가 따로 있어서 그쪽이 잡아야 하는데, 재보니 못 잡습니다.

```
경로 유사도 (과거 시도 120건과 대조)
  공격   중앙 0.9498   0.9 이상 59/60
  사람   중앙 0.9592   0.9 이상 60/60     ← 사람이 더 비슷하다
```

**메인 캡차에서는 모두가 서로 닮았습니다.** 작은 객체를 짧게 끌어 정답존에 넣는
동작이라 경로가 다 비슷합니다. 유사도로는 아무것도 못 가릅니다.

### 그래서 결론은 모델이 아니라 상호작용 설계다

```
레거시 궤적      세션당 340 이벤트
메인 캡차 드래그   12 이벤트          ← 28배 적다
```

**12개 점에는 사람과 봇을 가를 재료가 충분하지 않습니다.** 모델을 바꿔서 될 문제가
아닙니다. 세 가지가 전부 같은 곳을 가리킵니다.

```
사람 오탐이 33.3% 로 튄 것        정보가 적어 사람끼리도 안 갈림
진화 공격이 83.5% 통과하는 것      12점을 흉내 내는 건 쉬움
재생 유사도가 사람 0.96 / 봇 0.95  경로가 원래 다 비슷함
```

### 할 수 있는 것

```
1  드래그 수를 늘린다      세션당 2~3개면 중앙값 채점의 재료가 는다
                          (이미 per-drag median 으로 받을 준비는 돼 있다)
2  드래그를 길게 만든다     객체를 더 멀리, 경로에 장애물
3  다른 신호를 더한다       클릭 전 hover, 문항 간 이동, 스크롤
                          — 지금은 드래그 중만 본다
```

**1번이 제일 싸고 민서와 상의할 사안입니다.** 캡차 난이도를 올리지 않고도
객체 2개 → 3개로 드래그 수를 늘리면 됩니다.
