# 발표 전 공부 자료 — 처음부터

조성원 · 2026-08-05

> 발표에 나오는 개념을 순서대로 설명한다. 앞에서 뒤로 읽으면 뒤가 이해되게 썼다.
> 숫자는 전부 우리가 실제로 잰 값이다.

---

# 1부. 우리가 만든 것이 무엇인가

## 1-1. 캡차는 무엇을 하나

캡차는 **"이 문제를 풀 수 있느냐"** 를 묻습니다.

```
"사진에서 baby 코끼리를 정답존으로 옮기시오"
```

사람은 풉니다. 옛날 프로그램은 못 풀었습니다. 그래서 캡차가 작동했습니다.

## 1-2. 왜 부족해졌나

지금은 이미지 인식이 쌉니다. 멀티모달 AI에 사진과 문제를 넣으면 **학습도 없이**
답이 나옵니다. 즉 **"풀 수 있느냐"로는 더 이상 안 갈립니다.**

## 1-3. 그래서 우리가 본 것

**"어떻게 풀었느냐"** 입니다.

```
캡차       무엇을 풀었나   ← 답이 맞았나
행동 판별   어떻게 풀었나   ← 마우스가 사람처럼 움직였나
```

답을 맞혀도 **움직임이 사람의 것이 아니면** 걸러냅니다. 이게 제가 만든 층입니다.

**실제 사례** — 제가 브라우저 자동화로 캡차를 풀어봤는데, 답은 맞았는데 이렇게 왔습니다.

```json
{"success": false, "step_up": true, "risk_level": "suspicious"}
```

정답인데 통과 못 했습니다. 동작이 봇이었기 때문입니다.

# 2부. 알아야 할 용어 여섯 개

## 2-1. 특징 (feature)

마우스 궤적은 그냥 점들의 나열입니다. 컴퓨터가 판단하려면 **숫자로 요약**해야 합니다.
그 숫자 하나하나가 특징입니다.

```
궤적:  (10,20) → (12,23) → (15,27) → ... 점 340개

특징으로 요약:
  평균 속도          0.096
  최고 속도          2.80
  방향 전환 횟수      9회
  멈춤 횟수          6회
  목표 초과 후 되돌림  0회
  ...총 50개
```

**우리 모델은 이 50개 숫자만 봅니다.** 원본 궤적은 안 봅니다.

## 2-2. 학습 (training)

사람 궤적 2만 건, 봇 궤적 1만 3천 건을 주고 **"이 50개 숫자가 이렇게 생기면 사람"**
을 스스로 찾게 합니다. 규칙을 사람이 안 써줍니다.

왜 규칙을 안 쓰냐면 — **사람의 움직임에 정답이 없기 때문**입니다. 빠른 사람, 느린 사람,
트랙패드 쓰는 사람이 다 다릅니다.

## 2-3. 점수와 임계값

모델은 **0~1 사이 숫자**를 냅니다. 1에 가까우면 사람 같다는 뜻입니다.

```
human_probability = 0.9999  →  사람 같다
human_probability = 0.0296  →  봇 같다
```

여기서 **어디부터 사람으로 볼지** 선을 그어야 합니다. 그 선이 **임계값**입니다.

```
임계값 0.5로 정하면    0.6은 사람, 0.4는 봇
임계값 0.9로 정하면    0.6도 봇
```

**임계값을 올리면 봇을 더 잡지만 사람도 더 걸립니다.** 이 맞바꿈이 이 프로젝트 내내
따라다닙니다.

## 2-4. 오탐률(FRR)과 통과율(ASR)

```
FRR (False Rejection Rate)   사람인데 봇이라고 한 비율
ASR (Attack Success Rate)    봇인데 통과한 비율
```

둘 다 낮아야 좋습니다. 그런데 임계값 하나로 조절하니 **한쪽을 낮추면 다른 쪽이 올라갑니다.**

```
임계값 높임  →  FRR 올라감(사람이 막힘) · ASR 내려감(봇이 막힘)
임계값 낮춤  →  FRR 내려감            · ASR 올라감
```

우리 목표는 **FRR ≤ 3%, ASR ≤ 10%** 를 동시에 만족하는 것입니다.

## 2-5. 두 뷰 융합 (min fusion)

특징 50개를 두 갈래로 나눠 **각각 다른 모델**에 학습시켰습니다.

```
general    일반 궤적 특징 47개    (속도·방향·멈춤·엔트로피…)
dynamics   물리 특징 41개         (가속도·저크·회전각…)
```

그리고 **둘 중 낮은 점수**를 씁니다.

```
general이 0.99, dynamics가 0.02  →  최종 0.02  (봇)
```

**왜 낮은 쪽이냐** — 한쪽만 이상해도 걸리게 하려고요. 봇이 두 관점을 **동시에** 속여야
합니다.

## 2-6. 홀드아웃 (봉인 시험지)

**모델을 만드는 동안 절대 안 열어보는 데이터**입니다. 다 만든 뒤 딱 한 번 채점합니다.

시험 공부에 비유하면 이렇습니다.

```
문제집     공부용        = 학습 데이터
모의고사   실력 확인용    = 개발 중 평가
실전 시험  미리 못 봄     = 홀드아웃
```

**왜 필요하냐** — 공부한 데이터로 시험 보면 점수가 뻥튀기됩니다. 실제로 우리가 당했습니다.

```
7/22 후보 모델
  공부한 데이터로 잰 오탐률    2.39%   "괜찮네"
  봉인 시험지로 잰 오탐률      9.06%   탈락
```

**4배 차이.** 봉인 시험지가 없었으면 그 모델을 좋다고 올렸을 겁니다.

**한 번 열면 끝**입니다. 결과를 보고 모델을 고치면, 그 시험지도 공부한 데이터가 되니까요.

# 3부. 이상 행동을 어떻게 잡나 — 4계층

궤적 하나만 보면 흉내낼 수 있습니다. 그래서 네 층을 함께 봅니다.

## ① 궤적 — 사람은 망설이고 지나치고 되돌린다

학습 데이터에서 실제로 갈린 특징들입니다.

| | 사람 | 봇 |
|---|---:|---:|
| 방향 전환이 있는 비율 | **88%** (평균 4.9회) | 47% (2.0회) |
| 멈춤이 있는 비율 | **98%** (평균 24.6회) | 59% (9.4회) |
| 목표를 지나쳤다 되돌린 비율 | **47%** | 19% |
| 종점에서 보정한 비율 | **39%** | 23% |

사람은 목표를 향해 곧게 안 갑니다. **망설이고, 지나치고, 되돌립니다.**

## ② 타이밍 구조 — 멈췄다 다시 움직일 때

사람은 멈췄다가 다시 움직일 때 **관성이 남습니다.** 프로그램은 딱 멈추고 딱 출발합니다.
이걸 `stop_go` 패턴으로 따로 잡습니다.

## ③ 전송 방식 — 이게 핵심입니다

이벤트를 **200ms마다 서버로 보냅니다.** 그런데 긴 궤적을 **마지막에 한 번에 몰아 보내면**
브라우저에서 실시간으로 만들어진 게 아닙니다.

```
사람     그리는 동안 계속 도착         200ms · 400ms · 600ms …
봇      다 만들어놓고 한 번에 도착      마지막에 몰아서
```

**클라이언트 시각은 위조할 수 있지만, 서버가 받은 시각은 못 속입니다.**

## ④ 실행 환경

```
navigator.webdriver 가 true    +80점
헤드리스 브라우저 UA           +80점
언어 설정 없음                 +15점
CPU 코어 0                     +10점
```

자동화 브라우저의 순정 흔적입니다.

# 4부. 우리가 찾은 결함 세 개

여기가 발표의 알맹이입니다.

## 4-1. 이상을 "규모"로 재고 있었다

특징 중 일부가 **세션 전체의 합계**였습니다. 이벤트 수, 총 시간, 총 이동 거리.

그런데 이 값들은 **드래그를 여러 번 하면 그냥 커집니다.**

```
자로 그은 완전한 직선

  1번 끌면   0.0296   차단
  5번 끌면   0.9996   통과
```

**같은 궤적입니다.** 공격자에게 "여러 번 끌기"는 반복문 한 줄입니다.

**고친 방법** — 드래그마다 따로 채점하고 중앙값을 씁니다. 직선 5개는 여전히 직선 5개입니다.

그리고 고치니 **가려져 있던 게 드러났습니다.**

```
사람 중 드래그 2회 이상인 세션 56건
  세션 합계로 채점    53/56 통과
  드래그별로 채점      4/56 통과
```

다중 드래그 사람이 통과하던 건 **모델이 알아봐서가 아니라 합계가 부풀어서**였습니다.

## 4-2. 특징이 화면 크기에 딸려 있었다

좌표를 픽셀로 계산했습니다. 그런데 캡차 크기가 화면마다 다릅니다.

```
그림판 500칸일 때   손이 100칸 움직임
그림판 375칸일 때   같은 손동작이 75칸으로 기록됨
```

50개 중 **17개가 이 크기에 딸려 다녔습니다.** 비율 좌표(0~1)로 바꾸니 성능이
오히려 좋아졌습니다.

**절대 크기는 신호가 아니라 잡음이었습니다.**

## 4-3. 레드팀이 60배 약했다 — 제일 중요

### 레드팀이 뭔가

우리가 **직접 만든 공격 봇**입니다. 방어가 잘 되는지 확인하려면 공격해봐야 하니까요.

### 기존 방식의 문제

봇 궤적을 **무작위로** 만들어 뚫리는 걸 셌습니다. 그런데 같은 모델에 **시드만 바꿔**
여섯 번 돌리니 이랬습니다.

```
회피 28건 · 0건 · 21건 · 18건 · 1건 · 17건
```

**0건이 나온 시드로 봤으면 "완벽하다"고 발표했을 겁니다.**

> **시드(seed)** — 난수를 만드는 시작값. 같은 시드면 같은 무작위 결과가 나옵니다.
> 시드를 바꾸면 완전히 다른 봇들이 만들어집니다.

### 실제 공격자는 이렇게 안 한다

무작위로 계속 뽑는 게 아니라, **먹힌 걸 남기고 그 주변을 팝니다.**

```
1세대   40개 정책을 무작위로 만들어 점수 매김
        상위 8개만 남김
2세대   그 8개를 조금씩 변형해서 40개 만듦
        다시 상위 8개
...30세대까지 반복
```

이걸 **진화 탐색**이라고 합니다. 결과가 이렇게 나왔습니다.

```
무작위 스윕   0.7%      ← 우리가 알던 값
진화 탐색     47%       ← 실제
```

**우리 측정 도구가 공격을 60배 과소평가하고 있었습니다.**

# 5부. 어떻게 막았나

## 5-1. 왜 임계값으로 안 되나

공격자가 찾은 점들은 **모델이 "사람"이라고 답하는 영역 안**에 있습니다. 정의상 그렇습니다.
임계값을 어디에 두든 그 안쪽입니다.

```
┌──────────────────────────────┐
│   모델이 "사람"으로 보는 영역     │
│                              │
│    ●실제 사람들이 모여 있는 곳    │
│                              │
│              ★ ← 공격자가 찾은 빈 자리 │
└──────────────────────────────┘
```

★는 **사람이 한 명도 없는 자리인데 모델은 사람이라고 합니다.** 네모 크기를 조절해도
★는 안쪽입니다.

## 5-2. 그래서 질문을 하나 더 던졌다

**"실제 사람들 근처에 있는가"**

| | 사람 데이터까지 거리 |
|---|---:|
| 진짜 사람 | **2.0** |
| 처음 보는 사람 | **2.0** |
| 공격자가 찾은 점 | **5.6** |
| 일반 봇 | 8.6 |

**처음 보는 사람도 2.0입니다.** 사람은 누구든 사람들 근처에 있고, 공격자의 점은 2.8배
멀리 있습니다.

## 5-3. 그런데 진짜 해결은 다른 데서 나왔다

7월에 레드팀이 찾아낸 약점 **2,554건이 학습에 안 들어간 채 방치**돼 있었습니다.
넣고 다시 학습하니:

```
회피율      47%  →  6%
사람 오탐   1.62% → 1.17%   (좋아짐)
```

크기 정규화까지 하니 **3.3%** 가 됐습니다.

**왜 아무도 안 넣었냐면** — 7월에 비슷하지만 다른 데이터로 시도했다가 사람 오탐이
2.4% → 9%로 튀어 실패한 적이 있었습니다. 그 결론이 "약점 학습은 안 된다"로 굳어졌고,
저도 확인 없이 받아 적었습니다.

**틀린 결론 하나가 3주를 막고 있었습니다.**

# 6부. 승급이 뭐고 왜 못 했나

## 6-1. 세 단계

```
shadow      점수만 기록. 사용자에게 영향 없음     ← 지금 여기
step-up     의심되면 문제를 한 번 더 풀게 함
enforce     의심되면 차단
```

지금은 **shadow** 입니다. 모델이 "봇"이라고 해도 아무 일도 안 일어납니다.

## 6-2. 왜 못 올렸나

성능은 기준을 통과합니다.

| 항목 | 기준 | 현재 |
|---|---|---|
| 미지 공격 회피율 | ≤10% | **3.3%** ✅ |
| 알려진 봇 통과 | ≤5% | 3.6% ✅ |
| **검증용 참여자** | 5명 | **2명** ❌ |
| **봉인 시험지** | 필요 | **소진** ❌ |

**성능이 부족해서가 아니라, 통과했다고 말할 근거가 부족해서입니다.**

사람 데이터가 2명이라 "오탐률이 X%다"라고 말할 수 없고, 봉인 시험지를 다 써버려서
새 모델을 검증할 수단이 없습니다.

## 6-3. 왜 기준을 안 낮췄나

**7월 30일에 결과를 보기 전에** 기준을 정했습니다. 그리고 33%라는 나쁜 숫자를 보고도
안 고쳤습니다.

숫자를 보고 기준을 고치면 **그 기준이 의미를 잃습니다.**

# 7부. 못 잡는 것

| | 왜 |
|---|---|
| **사람 대행 서비스** | 진짜 사람이 풉니다. 행동으로는 원리적으로 불가 |
| **시각 인식 봇** | 답은 맞힙니다. 동작까지 사람처럼 만들면 뚫립니다 |
| **재생 조작** | 배속·탭 숨김은 **포인터를 아예 안 건드립니다** |

세 번째가 인강 사이트에서 제일 흔한데, **행동 판별이 원리적으로 못 봅니다.**
진짜 사람이 앉아 있고 자동화는 재생만 제어하니까요.

다만 싸게 잡힙니다 — **진도 증가량 ÷ 실제 경과 시간** 비율만 보면 됩니다. 16배속으로
파밍하면 비율이 16이 됩니다. 공격자가 못 속입니다. 천천히 보내면 파밍 자체가 안 되니까요.

# 8부. 발표에서 나올 질문에 답하는 법

**"실서비스에서 봇을 막고 있나요?"**
→ 아직 아닙니다. 점수만 기록하는 shadow 상태이고 위젯 연동이 남았습니다.

**"오탐률이 몇 퍼센트인가요?"**
→ 참여자가 2명이라 숫자를 말씀드릴 수 없습니다. 2명 기준 1.2~4.5%인데, 그 폭 자체가
표본 부족이라는 뜻입니다.

**"3.3%는 믿을 수 있나요?"**
→ 저희가 만든 가장 강한 공격자 기준입니다. 더 강한 공격자를 만들면 올라갈 수 있습니다.
다만 이전 도구가 60배 과소평가했던 걸 감안하면 지금 숫자가 훨씬 정직합니다.

**"규칙 기반으로는 안 되나요?"**
→ 사람 움직임에 정답이 없어 규칙으로는 못 씁니다. 다만 **명백한 하한**은 규칙으로 씁니다.
드래그당 중간 이동이 2개 미만이면 사람이 아닙니다 — 사람은 최소 2.3개, 중앙값 11개인데
순간이동 봇은 정확히 1개입니다.

**"왜 기준을 낮추지 않았나요?"**
→ 7월 30일에 결과를 보기 전에 정했습니다. 숫자를 보고 고치면 의미를 잃습니다.
